# PART 5 피날레. 다음 영상에도 쓸 제작 방식을 갖췄습니다

처음에는 질문 하나였습니다.

> “항구를 쇠사슬로 막았는데, 배는 어떻게 안으로 들어갔을까요?”

지금은 숲속의 함선과 육상 운반, 항만 안쪽의 결론이 이어지는 영상이 있습니다. 카메라가 공간을 공개하고, 목소리가 맥락을 더하고, 짧은 자막이 마지막 답을 남깁니다.

> **돌파가 아니라, 우회였습니다.**

사례에서는 한국어판과 영어판을 각각 82초로 출력하고 표지·제목·설명·출처 등 게시 자료까지 준비했습니다. 실제 업로드와 공개 뒤 성과 관찰은 아직 하지 않았습니다. 제작 스킬의 역할도 완성 파일과 게시 자료 준비까지입니다. 공개를 선택하면 준비한 자료로 YouTube Studio에서 직접 등록합니다. 자동 등록이나 댓글 운영 도구를 추가로 만들지는 않습니다. 독자도 자신의 목표에 맞춰 선택한 언어의 완성본과 게시 준비를 마친 뒤 공개 여부를 결정할 수 있습니다.

## 장면마다 무엇을 보여 줄지 골랐습니다

장면으로 보여 줄 질문을 고르는 데서 시작했습니다. 자료를 읽으며 설명용으로 재현할 부분과 사실로 단정하면 안 되는 부분을 나눴습니다.

반복 등장할 함선은 하나의 기준으로 만들었습니다. 원화마다 각도·빛·전경·카메라 통로를 달리해 같은 대상도 다른 사건으로 보이게 했습니다. 실제 결과에 후대 건물이나 어색한 지지 관계가 보이면 필요한 장면만 고쳤습니다. 좋은 원화 두 장이라도 방향과 인력이 달라지면 연속 프레임으로 억지로 연결하지 않았습니다.

편집 단계에서는 실제 화면과 목소리에 맞춰 계획한 시간을 조정했습니다. 대본이 길면 줄이고, 글자가 많으면 덜었습니다. 화면을 설명하는 선도 최종판에서는 덜어냈습니다.

| 남은 결과물 | 다음에 다시 쓸 수 있는 것 |
|---|---|
| 질문·근거·장면표 | 조사와 시각 사건을 연결하는 방법 |
| 대상 참조·번호 원화·영상 | 외형을 유지하며 장면을 달리하는 방법 |
| 편집 명세·음성 배치 | 실제 길이로 화면과 말을 맞추는 방법 |
| 음향 큐·권리 기록·자막 소스 | 소리와 글자를 따로 고치는 방법 |
| 완성 파일·표지·게시 자료 | 내용과 시청자의 기대를 맞추는 방법 |

## 스킬에는 다음 편의 출발점이 남았습니다

18장의 `book-shorts-plan`, 19장의 `book-shorts-build`, 20장의 `book-shorts-finish`는 이번 영상의 숫자를 반복하는 도구가 아닙니다. 자신의 소재와 자료를 넣고 현재 단계의 판단과 결과를 남기는 출발점입니다.

다음 영상에는 캐릭터가 둘일 수도 있고 원화가 더 필요할 수도 있습니다. 설명을 오래 읽혀야 하는 장면이 있을 수도, 소리 없이 보여주는 편이 좋은 장면이 있을 수도 있습니다. 함선 영상의 9장·9클립·82초를 그대로 정답으로 옮기지 않습니다.

새 소재를 시작할 때는 이번 프로젝트의 좋은 결과를 보존하고 별도의 프로젝트를 준비합니다. 앞에서 만든 것은 프로젝트 로컬 스킬이므로 새 폴더에서 자동으로 발견된다고 가정하지 않습니다.

자신이 본문의 공개 명세로 만든 `book-shorts-plan` 파일과 필요한 공개 양식만 새 프로젝트의 지원 위치에 복사·등록할 수 있습니다. 이전 프로젝트의 진행 상태·계정·미디어는 그대로 둡니다. 스킬을 찾을 수 없으면 18장의 완전한 생성명세로 새로 만들고 호출법을 확인합니다. 스킬 기능이 없는 AI에는 명세 파일을 읽게 하는 직접 요청 경로를 사용합니다. 저자의 비공개 스킬은 어느 방법에서도 필요하지 않습니다.

## 마지막에 남은 것은 결과물만이 아닙니다

1장에서는 공식 영화 기록으로 Excel 보고서를 만들었습니다. 이후 실제 데이터를 연결한 서비스와 웹 챗봇, 핵심 기능을 선택한 두 앱, 목소리와 음향·자막을 합친 영상으로 결과물의 범위를 넓혔습니다.

개발에 쓰는 AI, 학습을 돕는 튜터, 서비스 안에서 질문에 답하는 AI는 역할이 다릅니다. 제작 AI는 프로그램과 파일을 만들고 고칩니다. 튜터는 준비·단계·완료 조건을 함께 확인합니다. 서비스의 AI는 허용된 자료와 기능 안에서 사용자의 질문을 처리합니다.

사람에게는 무엇을 만들지, 어떤 자료를 근거로 믿을지, 어디까지 실행할지를 정하는 판단이 남았습니다. 실제 확인한 결과와 미실시한 단계도 구분해 기록합니다. 게시를 선택하지 않은 영상은 제작 완료와 게시 미실시를 따로 남기면 됩니다.

부록 A에서는 자료를 찾고, 부록 B에서는 막힌 작업을 다시 이어갑니다. 부록 E에서는 사용한 기술을 정리하고, 부록 G에서는 무엇을 만들고 어떤 판단을 했으며 어떻게 확인했는지를 포트폴리오로 보여줍니다.

다음 프로젝트에서는 자신이 자주 확인하는 문제부터 골라봅니다. 자료와 기능을 연결하고 작은 결과를 확인한 뒤 필요한 범위로 넓혀가면 됩니다.
