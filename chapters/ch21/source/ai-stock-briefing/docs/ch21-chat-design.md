# 주식서비스 챗봇 기획서 (21장 설계 / 22장 구현)

이 문서는 21장에서 확정한 결정만 담는다. 21장에서는 제품 코드를 바꾸지 않고, 22장에서 이 문서대로 전체 대화 기능을 구현한다. 기존 시장·검색·상세·차트·공시·AI 브리핑·Database/Cache·모바일 기능과 디자인은 그대로 보존한다. 운영 기본값은 chat OFF다.

> 이 파일은 구현과 함께 두는 사본이다. 가격 질문 두 방식(최근 확인 종가 / 기간 흐름 요약)은 구현 확정에 맞춰 이 사본을 먼저 고쳤다.
>
> **2026-09-14 범위 축소.** 이 실습은 **로컬에서 켜서 확인하는 대화 기능**까지만 다룬다. 공개 배포 운영을 위한 장치(공용 사용량 제한 저장소, 접속 출처 식별, 배포 우회 설정)는 21–22장에서 만들지 않기로 결정해 이 문서에서도 뺐다. 한 질문 안의 상한(모델 3회·조회 4회·전체 30초)과 질문 길이 제한은 그대로 둔다. 기존 브리핑 Cache·Redis 기능은 손대지 않는다.

## 1. 기능과 범위

### 지원하는 질문

| 대표 질문 | 답변 방식 | 조회 |
|---|---|---|
| “변동성이 뭐야?” | AI 일반 설명만 | 없음 |
| “환율은 수출기업에 어떤 영향을 줄 수 있어?” | AI 일반 설명만 | 없음 |
| “이 종목의 최근 확인 종가와 기준일을 알려줘.” | 확인된 자료 | 가격 요약 |
| “…가격을 볼 때 기준일을 확인해야 하는 이유도 설명해줘.” | 확인된 자료 + AI 일반 설명 | 가격 요약 |
| “삼성전자의 최근 공시 5건을 DART 원문과 함께 보여줘.” | 확인된 자료 | 종목 찾기 + 공시 목록 |
| “최근 3개월 가격 흐름 알려줘.” | 확인된 자료 | (필요 시 종목 찾기 +) 가격 요약 |

일반 설명은 금융용어에 한정하지 않는다. 경제·기업·데이터·AI처럼 주식 자료를 이해하는 데 관련된 개념까지 다룬다.

### 제외하는 질문

- 특정 기업의 현재 사업·실적·최근 사건·현재 수치·뉴스·주가 변동 원인을 모델 사전지식으로 채우는 답변
- 투자 추천·매수/매도 판단·목표가·미래 가격 예측·고평가/저평가 판단
- 공시 본문 수집과 본문 요약, 자유 웹 검색, 지수 비교, 임의 시작·종료일 기간
- 서비스와 무관한 주제(요리·여행 등) → 지원 범위 안내 한 줄

### 답변 영역

| 영역 | 내용 | 표시 규칙 |
|---|---|---|
| 확인된 자료 | 서버가 확인·계산한 종목·수치·날짜·가격 요약·공시·출처 | 가격 기준일, 실제 첫/마지막 거래일, 답변 준비 시각 표시 |
| AI 일반 설명 | Gemini 사전지식의 관련 개념·일반 원리 | `최신 확인 자료가 아닙니다` 고정 표시 |
| 지원 범위 안내 | 확인 자료가 없거나 범위 밖일 때 다음 행동 2개 이내 | 상태 메시지이며 필수 카드가 아님 |

일반 질문에는 빈 자료 카드를 만들지 않는다. 형식 검사로 문장 의미가 정확해진다고 설명하지 않는다. 화면에는 Cache hit/miss·TTL·함수명·JSON·모델/도구 호출 번호·request ID·근거 ID를 노출하지 않고, 실제 수행 내역만 `종목 찾기 → 공시 조회`처럼 사용자 언어 한 줄로 표시한다.

## 2. 사용 흐름

| 상황 | 서버 동작 | 다음 행동 |
|---|---|---|
| 일반 개념 질문 | 조회 0회, 일반 설명만 | 이어서 질문 |
| 메인의 종목 질문 | 질문에서 회사명·코드를 뽑아 실제 검색으로 확인 | 정확히 하나면 바로 진행 |
| 검색 결과가 모호 | 실제 후보 최대 5개 제시, 가격·공시 조회 0회 | 후보 선택 또는 취소 |
| 후보 선택 | 보관한 원래 질문을 서버가 후보 재검증 후 이어서 처리 | 답변 표시 |
| 상세 화면 질문 | `이 종목`은 서버가 다시 확인한 route 종목(최초 기본값) | 답변 표시 |
| 다른 종목 명시 | 뒤의 상세 화면은 유지하고 대화 대상만 전환 | 이후 후속 질문은 바뀐 대상 우선 |
| 실제 route 이동 | 새 대화로 초기화 | 다시 질문 |
| 검색 실패·취소·AI 실패 | 질문을 잃지 않고 입력창에 유지 | 재질문 또는 범위 안내 |

대상 전환 시 이전 종목의 근거와 대화 history는 지우고, 전환을 요청한 새 질문은 유지한다. 이전 대상의 늦은 응답은 붙이지 않는다.

### 브라우저 상태 계약

- 질문 원문·후보·최근 3회 왕복·현재 대화 대상은 React 메모리로 현재 탭에만 보관한다.
- `sessionStorage`·`localStorage`·Cookie를 쓰지 않는다. 새로고침·페이지 이동·지우기로 끝난다.
- 서버에는 pending selection이나 대화 state를 저장하지 않는다.
- 서버는 브라우저가 보낸 회사명·시장·기준일·종목코드·과거 대화를 사실 근거로 신뢰하지 않고 매 요청 다시 확인한다. 최근 3회 history는 언어 문맥일 뿐이며 `system`·`tool`·`function` 역할과 임의 evidence/source 필드는 거부한다.
- 브라우저는 request ID와 local generation을 쓰고, 지우기·route/대상 변경 때 generation을 올려 이전 요청을 무시한다. 이미 시작된 서버 호출과 과금까지 중단한다고 약속하지 않는다.

## 3. 위치와 디자인

- 공통 layout에 독립된 leaf Client Component로 추가한다. 닫힌 동안 외부 자료나 Gemini를 호출하지 않는다.
- 오른쪽 아래 플로팅 버튼: 기존 하단 조작을 가리지 않는 위치를 실제 화면과 대조해 확정한다.
- 데스크톱: 오른쪽 대화 레이어. 모바일 웹: 키보드와 하단 안전 여백을 고려한 큰 레이어. 별도 모바일 앱은 수정하지 않는다.
- 레이어 구성(위→아래): 현재 대화 대상(회사명·종목코드·`이 종목 상세 보기`) → 대화 목록 → 전송 상태 → 입력창·전송 → 대화 지우기·닫기.
- 답변 순서: 확인된 자료를 먼저, AI 일반 설명을 그다음에 둔다. **두 영역 모두 기본으로 펼쳐 보여준다.** 접는 것은 공시 전체 목록·거래일 구간 같은 추가 근거뿐이며, 일반 설명 자체를 접지 않는다.
- 색·글꼴·카드·여백은 기존 서비스 값을 그대로 따른다. 새 디자인 언어를 만들지 않는다.

검사 항목: 닫기 후 원래 화면 복귀와 키보드 포커스 복귀, 키보드가 올라온 상태에서 입력창·전송 버튼·마지막 답변 가시성, 스크롤, 하단 안전 여백, 390×844 모바일 웹, 중복 제출 방지.

## 4. 기존 기능 연결표

| 역할 | 기존 함수 | 입력 | 결과 | 실패 상태 | Cache 의미 |
|---|---|---|---|---|---|
| 종목 찾기 | `searchStocks` (`src/lib/stock.ts:47`) | 검색어 문자열 하나(챗봇은 50자 이내) | `{ baseDate, hits }` — `hits`는 이 함수가 이미 최대 20건으로 자른 목록 | 빈 결과 → 후보 없음 안내 | 하위 `fscFetch` 경로에 의존 |
| 가격 기준일 | `resolveLatestPriceBaseDate` (`src/lib/market.ts:31`) | 없음 | 최근 확인 가격 기준일 문자열 | 최근 20일 자료 없음 → 예외, 가격 답변 불가 안내 | 하위 `fscFetch` 경로에 의존 |
| 일봉 수집 | `fetchStockHistory` (`src/lib/stock.ts:96`) | 종목코드·기준일 두 인자 | `{ quote, bars }` — 최근 확인 하루 시세 하나(없으면 `null`)와 최근 1년 일봉 배열 | 자료 없음 → `quote`가 `null`이고 `bars`가 빈 배열, 실제 제공 구간 안내 | 하위 `fscFetch` 경로에 의존. 같은 요청 안에서 재수집하지 않음 |
| 가격 계산 | `summarizePriceHistory` (`src/lib/briefing-facts.ts:6`) | 일봉 배열 | 가격 요약 | 빈 배열이면 예외 | 없음(순수 계산) |
| 회사 매핑 | `findCorpByStockCode` (`src/lib/dart.ts:59`) | 종목코드 | DART 회사 또는 `null` | `null` → 공시 조회 불가 안내 | **데이터 Cache가 아니다.** 저장된 JSON 스냅샷(`src/data/dart-corp-map.json`)을 module 적재 때 메모리 Map으로 만들어 쓴다. 외부 호출도 만료도 없다 |
| 공시 목록 | `fetchFilings` (`src/lib/dart.ts:64`) | 회사코드·기간·페이지 옵션 객체 | `{ filings, totalCount, pageNo, totalPage }` + 서버가 접수번호로 만든 DART 원문 URL | 빈 목록 → 해당 기간 공시 없음. 상태코드 이상 → 예외 | OpenDART를 `fetch`로 직접 부르며 **Next fetch Cache `revalidate: 600`초**를 쓴다(12장 측정 옵션이 켜지면 `no-store`) |
| 외부 호출 | `fscFetch` (`src/lib/fsc.ts:58`) | endpoint·parameter·Cache 옵션 | `{ items, totalCount }` | 상위에서 실패 상태로 변환 | Supabase 스냅샷을 먼저 읽고, 없으면 금융위를 부른 뒤 Next fetch Cache(기본 600초)와 스냅샷에 남긴다 |

기존 함수의 의미·반환값·기존 Test는 바꾸지 않는다. 위 값은 실제 Source를 대조해 적었고, 반환 모양이 다른 함수(`fetchStockHistory`의 `{ quote, bars }`)는 Adapter에서 필요한 쪽만 꺼내 쓴다.

`searchStocks`가 최대 20건까지 돌려주고 챗봇이 후보를 5개만 보여주는 것은 **자른 것**이다. 자른 목록의 첫 항목을 확정된 하나로 보지 않는다. 대상이 하나로 확정되는 조건은 실제 결과가 정확히 1건일 때뿐이다.

### 그대로 재사용하지 않는 것

- `collectBriefingEvidence`를 챗봇의 최근 공시 묶음으로 쓰지 않는다.
- 모바일 API facade를 웹 챗봇 계약으로 쓰지 않는다.
- 브리핑 Redis 결과 Cache를 대화 state 저장소로 전용하지 않는다. 브리핑 Cache 자체는 그대로 둔다.
- 종목 질문마다 전체 `getMarketSnapshot`을 호출하지 않는다.
- 브리핑의 200거래일 미만 ‘자료 부족’ 판정을 짧은 기간에 적용하지 않는다. 계산 재사용과 판정 기준 재사용을 구분한다.
- 예시 숫자를 모두 금지하는 브리핑 검증기를 그대로 적용하지 않는다. 특정 기업의 미확인 현재 사실과 일반 개념의 예시를 구분한다.

## 5. 22장에서 최소로 추가할 것

1. 대화 API route 하나: 질문 1,000자 제한, 최근 3회 왕복 검증, 세 Tool 실행·검증, 두 답변 영역과 근거·카드·링크를 서버에서 만들어 반환.
2. 가격 Adapter: 가격 질문은 두 가지가 있고 **하나의 Tool이 두 방식을 지원한다.**
   - **최근 확인 종가(기간 없음).** “최근 확인 종가와 기준일은? 기준일이 왜 중요해?”처럼 기간을 말하지 않은 질문에는 확인된 마지막 거래일의 종가와 가격 기준일만 답한다. 기간을 되묻지 않고, 요청하지 않은 기간 요약을 만들지 않는다. 기준일에 거래일 자료가 없으면 그보다 앞선 거래일의 종가라는 사실을 밝힌다.
   - **기간 흐름 요약.** “최근 3개월 흐름”처럼 구간을 물을 때만 계산한다. 기간을 말하지 않은 흐름/구간 질문은 추측하지 않고 달력 1개월·3개월·12개월 중에서 되묻는다.

   기간 요약은 최근 1년 일봉을 요청 기간만큼 잘라 `summarizePriceHistory`에 넘긴다. 기간은 최근 확인 가격 기준일에서 서울 날짜로 거슬러 센 달력 1개월·3개월·12개월만 지원하고, 대응 날짜가 없는 월말은 그 달 말일을 쓴다. 22/66거래일을 달력 월과 동일시하지 않는다. 요청 범위·실제 첫/마지막 거래일·거래일 수·자료 부족을 구분해 표시하고, 기간이 모호하면 추측하지 않고 되묻는다.
3. AI Tool 정의 3개(기존 Gemini structured output과 validator pattern 재사용): 사용자 역할을 먼저 정하고 AI용 이름은 `find_stock`, `get_price_summary`, `list_disclosures`로 둔다. 기존 내부 함수명과 같은 것이라고 설명하지 않는다.
   - `find_stock`: 회사명·코드 50자 이내, 실제 후보 최대 5개. 정확히 하나면 진행, 모호하면 선택 전 가격·공시 조회 0회. **검색어는 AI가 적었다는 이유로 사용자가 말한 회사와 같다고 보지 않는다.** 이번 질문에 그대로 적힌 회사명·종목코드, 화면 문맥 코드(서버가 다시 검증), 사용자가 고른 뒤 확인된 대상만 검색 근거가 된다. AI가 더 좁은 회사명으로 바꿔 적으면 질문에 있는 말로 되돌려 검색하고(그래서 후보 선택으로 이어진다), 되돌릴 근거가 없으면 검색하지 않고 되묻는다. 회사명 사전을 만들거나 일반 질문에서 미리 조회하지 않는다.
   - `get_price_summary`: 확인된 한 종목. 방식은 두 개다. `latest`는 기간 없이 최근 확인 종가·기준일만, `range`는 달력 1/3/12개월 흐름 요약이다. 방식은 검증된 값만 받고, 기간을 채워야 한다는 이유로 사용자가 말하지 않은 12개월을 대신 고르지 않는다. **형식이 맞는 기간이라도 이번 질문에 적혀 있지 않으면 조회를 시작하지 않고 되묻는다**(`1개월`·`한 달`·`3개월`·`세달`·`석달`·`12개월`·`1년` 같은 표현을 지원하고, `요즘`·`최근`처럼 기간이 아닌 말과 지원하지 않는 기간은 되묻는다. 문장의 뜻을 이해하는 것이 아니므로 모르는 표현은 되묻는 쪽으로 남긴다). Tool 이름은 세 개 그대로 둔다.
   - `list_disclosures`: 확인된 한 종목, 최근 1년 안, 최신순 1~5건, DART 원문 링크. 본문을 읽거나 제목으로 영향을 단정하지 않는다.
4. 플로팅 버튼과 대화 레이어 Client Component(데스크톱·모바일 웹).

22장 완성본은 별도 활성화 설정 없이 대화 기능을 사용할 수 있다. 필요하면 `CHAT_ENABLED=false`로 끈다. 새 Key나 대화 전용 저장소 없이 기존 `GEMINI_API_KEY`·`GEMINI_MODEL`을 재사용한다. 공개 사용량 관리 장치를 만드는 실습은 포함하지 않는다.

호출 상한(초기값): 모델 3회·조회 4회·전체 30초. 모델 호출·도구 실행·하위 외부 API 호출은 서로 다른 수로 센다. 같은 HTTP 요청의 같은 Tool과 검증된 입력은 request-local Map에서 재사용한다. HTTP 재요청 사이의 중복 제거는 보장하지 않고, 재요청은 상한을 새로 세는 별개 요청이다. 자동 무한 반복과 자동 재시도는 만들지 않는다.

### 실패했을 때 돌아갈 방향

실패를 없애려고 제한을 느슨하게 바꾸지 않는다. 상한·검증·허용 목록을 우회하는 fallback은 만들지 않는다. 허용하는 대응은 세 가지뿐이다.

1. **멈춘다.** 확보한 자료까지만 표시하고 미확인을 밝힌다. 상한에 닿았을 때가 여기에 해당한다.
2. **범위를 줄인다.** 예를 들어 설명 검증이 실패하면 설명을 버리고 확인된 자료만 표시한다. 확인되지 않은 값을 채워 넣지 않는다.
3. **원인을 확인한다.** 인증·모델·형식·외부 응답·상한을 구분해 알린다.

어떤 경우에도 질문 원문은 잃지 않고, 확인되지 않은 값을 확인된 자료로 표시하지 않는다.

## 6. 구현 단계 (22장)

| 단계 | 만드는 것 | 대표 질문 | 화면에서 볼 결과 | 실패 시 돌아갈 지점 |
|---|---|---|---|---|
| S1 | 플로팅 버튼·대화 레이어·일반 설명(조회 0회) | “변동성이 뭐야?” | AI 일반 설명 + `최신 확인 자료가 아닙니다` | 레이어만 열고 이전 단계 유지 |
| S2 | 종목 찾기 + 공시 목록 + DART 원문 | “삼성전자의 최근 공시 5건을 DART 원문과 함께 보여줘.” | 확인된 자료 카드와 원문 링크, 수행 내역 한 줄 | S1 상태로 복귀 |
| S3 | 두 답변 영역과 출처 표시 정리 | 공시 + 개념 혼합 질문 | 확인된 자료와 일반 설명이 모두 펼쳐진 채 구분되고, 추가 근거만 접힘 | S2 답변 형식 유지 |
| S4 | 기간 Adapter·가격 요약·후속 대화·대상 전환 | “이 종목의 최근 확인 종가와 기준일을 알려주고, 기준일을 확인해야 하는 이유도 설명해줘.” | 종가·기준일·실제 거래일 구간 + 일반 설명 | 가격 기능만 비활성 |
| S5 | 상한·실패 처리·모바일 검수·회귀 | 후보 선택 재개, 악성 입력, 늦은 응답 | 범위 안내와 제한 메시지, 390×844 화면 | 멈추거나 범위를 줄이거나 원인을 알린다. 상한을 느슨하게 바꾸지 않는다 |

각 단계 끝에서 관련 Test를 먼저 실행하고, 전체 회귀는 장별 고정판에서 한 번 실행한다.

**자동 commit은 하지 않는다.** 기록이 필요한 지점(설계 / 구현·집중 Test / 회귀·촬영 인계)은 구분해 두지만, 각 단계 끝에서 저절로 commit·push·배포하지 않는다. 단계별 결과는 작업 tree와 `verification/` 기록으로 남기고, Git에 남길 시점은 사람이 따로 정한다.

## 7. 검증 기준

- 기존 Test 선언 전체가 그대로 통과한다. 기존 함수 의미·반환값·기존 Test를 바꾸지 않는다.
- 조회 횟수: 일반 질문 0회, 공시 질문에 가격 조회 0회, 후보 대기 중 가격·공시 조회 0회.
- 기간: 달력 1/3/12개월이 서울 날짜 기준으로 맞고, 월말 예외와 자료 부족 구간이 구분 표시된다. 기간을 묻지 않은 최근 종가 질문에는 기간을 되묻지 않고 종가·기준일만 답하며, 기간이 빠진 흐름 질문에만 되묻는다.
- 근거와 대상: 확인된 근거는 각자 어느 종목의 것인지와 함께 보관하고, 원본이 종목코드를 함께 돌려주면 그 값과 대조한다. 대상이 바뀌면 이전 근거는 쓰지 않고 버렸다는 사실을 밝힌다.
- 상태: 후보 선택 뒤 원래 질문이 이어지고, 대상 전환 때 이전 근거·history가 지워지며, 새로고침·페이지 이동으로 대화가 끝난다.
- 입력 검증: 1,000자 초과, 50자 초과 검색어, `system`·`tool`·`function` 역할, 임의 evidence/source 필드를 거부한다.
- 화면: 데스크톱과 390×844 모바일 웹에서 키보드·안전 여백·포커스 복귀·기존 UI 보존을 독립 검수한다.
- 실패 대응: 상한 도달·설명 검증 실패·외부 실패에서 상한이나 검증을 느슨하게 바꾸지 않고, 멈춤·범위 축소·원인 안내 중 하나로 끝난다.
- 세는 단위: 모델이 요청한 도구 수와 서버가 실제 실행한 수를 구분해 기록한다. 관측할 수 없는 외부 API 호출 수를 줄었다고 적지 않는다.
- 근거 대조: 실제 Gemini·가격·공시 응답과 화면 값을 대조하고, 통과한 상태만 촬영한다.
- 22장 완료 후 대화는 활성 상태다. 필요할 때 `CHAT_ENABLED=false`로 끌 수 있다.
