# 국내 주식 한눈에 모바일 앱 전환 계획

> 상태: 13장 의사결정 / 14장 Android / 15장 iPhone Golden Path 검증 완료
> 범위: Android·iPhone 공통 방향
> 범위 경계: Vercel Production Release HTTPS 연결은 검증했다. 실물 기기·Code Signing·스토어 배포는 미검증이다.

## 1. 전환 목적

현재 웹서비스는 시장 현황, 종목 검색, 종목 상세, 가격 차트, 공시 원문,
근거 기반 AI 브리핑을 제공한다. 웹만으로도 핵심 기능을 사용할 수 있으므로
앱은 부족한 웹서비스를 대신하기 위한 것이 아니다.

모바일 전환의 목적은 완성한 Backend를 유지한 채 같은 서비스를 Android와
iPhone이라는 새로운 Client에서 사용하는 경험을 만드는 것이다.

구현 순서는 다음과 같다.

1. 13장: 모바일 전환 필요성·범위·공통 계약 결정
2. 14장: Android 앱 구현과 실제 동작 검증
3. 15장: 같은 범위의 iPhone 앱 구현과 플랫폼 차이 재검증

## 2. 현재 구조 확인

현재 구현은 Next.js 기반 웹서비스다.

- 시장 화면: 서버 렌더링 페이지
- 종목 검색: 서버 렌더링 페이지
- 종목 상세·차트: 서버 렌더링 페이지와 Client Component
- 공시 목록·DART 원문 연결: 서버 렌더링 페이지
- AI 브리핑: `POST /api/stocks/[code]/briefing`
- 금융위원회·OpenDART·Gemini 호출: 서버 내부 로직
- Supabase Database·Redis Cache 접근: 서버 내부 로직

AI 브리핑을 제외한 핵심 데이터는 앱이 재사용할 수 있는 공통 JSON API로
아직 공개되어 있지 않다. 앱이 웹 페이지의 HTML을 읽거나 화면 코드를 복사해
데이터를 추출하게 만들지 않는다. 14장 구현 전에 기존 서버 로직 앞에 좁고
명확한 앱용 API 계약이 필요하다.

## 3. 앱에서 유지할 핵심 기능

| 기능 | 포함 여부 | 판단 |
|---|---:|---|
| 시장 기준일·코스피·코스닥 | 포함 | 첫 화면에서 시장 기준과 상태를 확인한다. |
| 급등주·급락주 | 포함 | 기존 웹서비스의 핵심 탐색 기능이다. |
| 종목 검색 | 포함 | 종목 상세로 들어가는 기본 경로다. |
| 종목 가격·거래 정보 | 포함 | 공식 데이터와 기준일을 함께 표시한다. |
| 최근 1년 차트 | 포함 | 웹과 같은 데이터 범위를 유지한다. |
| 최근 공시·유형·접수일 | 포함 | 가격과 공식 발표를 함께 확인한다. |
| DART 원문 열기 | 포함 | 앱 요약이 아니라 원문까지 내려갈 수 있어야 한다. |
| AI 브리핑 | 포함 | 기존 근거 묶음과 품질 기준을 재사용한다. |
| 브리핑 출처·한계 | 포함 | AI 답을 사람이 다시 확인할 수 있어야 한다. |
| 로그인·회원가입 | 제외 | 현재 핵심 기능에 필요하지 않다. |
| 관심종목 동기화 | 제외 | 계정과 개인정보 범위를 새로 만들지 않는다. |
| Push 알림 | 제외 | 권한·운영 범위를 불필요하게 넓힌다. |
| 매매·포트폴리오 | 제외 | 정보 확인 서비스의 목적을 벗어난다. |
| 관리자용 측정 API | 제외 | 독자용 앱 기능이 아니다. |

## 4. 공통 API 계약

아래 경로와 응답 형태는 14장 Android 구현과 실제 앱 호출로 확정했다.

| 목적 | 경로 | 방식 |
|---|---|---|
| 시장 요약 | `/api/mobile/market` | GET |
| 종목 검색 | `/api/mobile/stocks/search?q=` | GET |
| 종목 상세·차트 | `/api/mobile/stocks/[code]` | GET |
| 종목 공시 | `/api/mobile/stocks/[code]/filings` | GET |
| AI 브리핑 | 기존 `/api/stocks/[code]/briefing` 재사용 | POST |

공통 계약은 최소한 다음 기준을 지킨다.

- 웹과 앱이 같은 서버 로직과 공식 원천을 사용한다.
- 숫자에는 기준일·단위·출처를 함께 전달한다.
- 공시에는 접수일·유형·보고서명·DART 원문 주소를 전달한다.
- AI 브리핑에는 사용한 근거와 한계를 함께 전달한다.
- 외부 서비스의 내부 오류와 Secret을 응답에 포함하지 않는다.
- 앱이 처리할 수 있는 안정적인 오류 코드와 사용자용 메시지를 구분한다.
- 화면에 필요하지 않은 원본 응답 전체를 그대로 내보내지 않는다.
- Cache와 Database의 사용 여부가 결과의 의미를 바꾸지 않게 한다.

## 5. Client와 Server의 경계

앱이 담당할 일:

- 사용자의 검색어와 종목 선택을 받는다.
- 서버가 준 데이터·기준일·출처를 모바일 화면에 표시한다.
- 로딩, 빈 결과, 네트워크 실패, 사용 한도 상태를 구분해 보여준다.
- DART 원문을 안전한 외부 링크로 연다.

서버가 계속 담당할 일:

- 금융위원회와 OpenDART 인증
- Gemini 호출과 근거 묶음 생성
- Database·Cache 접근과 TTL 판단
- 숫자 계산과 AI 결과 검증
- Rate Limit과 외부 API 오류 처리
- Secret 보관

앱에는 다음 값을 넣지 않는다.

- `DATA_GO_KR_SERVICE_KEY`
- `OPEN_DART_API_KEY`
- `GEMINI_API_KEY`
- `SUPABASE_DATABASE_URL` 또는 Database 비밀번호
- `UPSTASH_REDIS_REST_TOKEN` 등 Redis 인증값
- 측정·관리용 Token

앱이 서버 주소를 아는 것은 필요하지만, 서버가 외부 서비스에 인증할 때 쓰는
Secret까지 알 필요는 없다.

## 6. 로그인·개인정보·권한

현재 앱 범위에는 로그인, 회원 프로필, 관심종목 동기화가 없다. 따라서 새
개인정보를 수집하거나 계정 Database를 만들지 않는다.

카메라, 마이크, 연락처, 위치, 사진과 같은 기기 권한도 핵심 기능에 필요하지
않다. 구현 중 새로운 권한이 필요하다는 제안이 생기면 기능 필요성, 수집
범위, 사용자 설명, 거부했을 때의 동작을 먼저 검토한다.

검색어와 종목 선택처럼 서버 요청에 포함되는 정보는 운영 로그에 불필요하게
오래 남기지 않는다. 외부 링크를 열 때는 DART 공식 주소인지 확인한다.

## 7. 모바일 화면 원칙

웹 화면을 작은 화면에 그대로 축소하지 않는다.

- 첫 화면에는 시장 기준일과 핵심 탐색 경로를 우선한다.
- 종목 상세에서는 가격·기준일·차트·공시·AI 브리핑의 순서를 분명히 한다.
- 긴 공시 목록과 출처는 접거나 별도 화면으로 나눌 수 있다.
- 숫자 단위와 상승·하락을 색상만으로 구분하지 않는다.
- 로딩, 데이터 없음, 외부 API 실패, AI 한도 도달을 서로 다르게 표시한다.
- AI 브리핑보다 공식 숫자와 출처를 먼저 확인할 수 있게 한다.

## 8. Android·iPhone 공통 완료 조건

각 플랫폼의 구현은 적어도 다음 시나리오를 실제 실행 환경에서 확인한다.

1. 앱을 열면 시장 기준일과 시장 요약이 나타난다.
2. 실제 종목명 또는 종목코드로 검색할 수 있다.
3. 선택 종목의 가격, 단위, 기준일, 차트가 웹과 같은 의미로 나타난다.
4. 최근 공시를 보고 DART 원문을 열 수 있다.
5. AI 브리핑을 요청하고 근거·출처·한계를 확인할 수 있다.
6. 같은 조건의 Cache 결과와 새 결과가 사용자에게 모순되게 보이지 않는다.
7. 네트워크 단절, 빈 결과, 외부 API 오류, AI 한도 상태를 구분한다.
8. Secret이 앱 패키지, 화면, 네트워크 응답, 로그에 노출되지 않는다.
9. 로그인과 불필요한 기기 권한 없이 핵심 흐름을 완료한다.
10. 웹의 투자 추천·예측 금지와 데이터 기준일 원칙을 그대로 지킨다.

Android와 iPhone에서 화면 모양이 완전히 같을 필요는 없다. 같은 기능과
근거, 안전 경계가 유지되는지가 더 중요하다.

## 9. 유지관리와 비용

앱이 생기면 웹만 운영할 때 없던 일이 추가된다.

- Android·iPhone OS 변경에 따른 호환성 확인
- 앱 빌드 도구와 의존성 업데이트
- 서버 API 계약 변경 시 두 앱의 영향 확인
- 기기 크기와 접근성 재검증
- 앱 서명, 개발자 계정, 스토어 정책 관리
- 장애와 외부 API 변경에 대한 앱 오류 처리

서버 API와 핵심 데이터 규칙을 공유하면 세 Client가 각자 외부 서비스를
호출하는 중복은 줄일 수 있다. 반대로 플랫폼별 기능을 무리하게 늘리면 검증과
유지관리 비용도 커진다. 첫 앱은 현재 핵심 기능으로 범위를 제한한다.

Google Play와 App Store 등록은 14·15장의 핵심 Golden Path가 아니다. 계정,
비용, 심사, 서명, 개인정보 표시처럼 빠르게 바뀌는 절차는 출간 직전 공식
자료로 다시 확인한다.

## 10. Android·iPhone 검증 결과

14장 Android Golden Path에서 다음 항목을 확정했다.

- Android 앱: 외부 라이브러리 없이 Android SDK와 Java로 만든 작은 Native Client
- Build: Android Gradle Plugin 9.3.1, Gradle 9.5.0, JDK 21, Build Tools 36.0.0
- SDK: compile/target API 37, 실제 실행은 Android 16/API 36 공식 Emulator
- 개발 연결: Debug에서만 `10.0.2.2:3000`을 허용하고 Release는 Vercel Production HTTPS 사용
- 권한: `INTERNET` 하나만 사용
- 앱 위치: `ai-stock-briefing/android`
- API: 위 표의 공통 JSON 계약과 기존 AI 브리핑 POST를 실제 호출

14장에서는 APK Build·Android Lint, 시장·상세 재검색·상승/하락 색상·SK하이닉스
244거래일 일봉 캔들·거래량·1개월/3개월/1년 전환·최근 공시, DART 외부 브라우저
전환, Gemini 브리핑과 Vercel Production Release HTTPS를 실제 Emulator에서
확인했다. 저장소와 APK Secret 검사도 통과했다.

15장 iPhone Golden Path에서 다음 항목을 확정했다.

- iPhone 앱: 외부 라이브러리 없이 SwiftUI·URLSession으로 만든 Native Client
- Build: Xcode 16.4, Swift 6, iOS 17 이상 Target
- 실제 실행: iPhone 16 Pro, iOS 18.6 공식 Simulator
- 개발 연결: Debug에서만 `127.0.0.1:3000` 로컬 연결을 허용하고 Release는 Vercel Production HTTPS 사용
- 앱 위치: `ai-stock-briefing/ios`
- 공유 범위: Android 화면 코드는 공유하지 않고 Next.js Server·공통 API 계약·데이터와 AI 안전 경계를 공유
- 검증: 시장·상세 재검색·상승/하락 색상·SK하이닉스 상세·244거래일 일봉 캔들·거래량·기간 전환·최근 공시, DART Safari 전환, Gemini 브리핑과 출처·한계
- 안전: Swift/Xcode Unit·UI Test, Release Build, ATS, 소스·Build 앱 Secret과 민감 권한 검사 PASS

실물 Android·iPhone, Code Signing, Google Play와 App Store 등록은 14·15장 PASS
범위가 아니다. 최신 계정 비용과 심사 정책은
출간 준비 단계에서 공식 자료로 다시 확인한다.
