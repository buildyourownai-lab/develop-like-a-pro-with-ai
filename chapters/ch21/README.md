# 21장. 내 주식서비스의 챗봇을 기획합니다

## 이 장에서 완성할 것
docs/ch21-chat-design.md에 기능 범위·답변 구분·사용 흐름·화면 설계·재사용 연결표·22장 구현 순서와 완료 조건을 확정합니다.

## 시작점
9~12장의 ai-stock-briefing으로 돌아옵니다. 기존 실행 방법과 설정을 재사용하며 14~15장 앱과 기존 작업을 보존합니다. 19~20장 완료는 선행 조건이 아닙니다.

현재 공개 주식서비스는 [stock.studyailab.com](https://stock.studyailab.com)에서 볼 수 있습니다. 아래 START·FINISH는 실습 비교용 고정 소스이므로 그 안의 과거 배포 주소와 현재 접속 주소를 구분합니다.

## 진행
이 장의 요청문 P21-01~P21-07은 Code 탭에서 순서대로 사용합니다. 질문 예시는 기획 사례이며 서비스 대화 실습이 아닙니다.

P21-01 시작 → P21-02 기능 범위 → P21-03 답변·사용 흐름 → P21-04 화면 설계 → P21-05 재사용 연결표 → P21-06 구현 계획 → P21-07 완료 확인

- [소스 연결 검증](../../verification/chapter-21/start-binding.md): 판본·파일 해시 검사 결과
- 실제 검증: `plan-build-v2`의 기획·구현·실제 API·화면 상태를 구분하며 미검증은 그대로 표시

기획서의 필수 목표와 제품 코드·Test 불변을 실제 파일 조사로 확인합니다. 기획 완료에 챗봇 실행·실제 API·촬영을 요구하지 않으며 구현 성공으로 표시하지 않습니다. 이전 실행 목표의 근거는 새 목표에 자동 승계하지 않습니다.

자기 프로젝트로 계속 진행할 수 있습니다. 비교 소스가 필요하면 별도 폴더에서 열고, 기존 작업과 로컬 설정을 덮어쓰지 않습니다. 소스 연결 검증은 독자 요청문 재현이나 실제 API 실행 성공을 뜻하지 않습니다.

완료한 챗봇은 기본 활성화하며 실제 자료와 활성 상태를 확인합니다. 새 범위의 독자 재현은 미실시입니다.
