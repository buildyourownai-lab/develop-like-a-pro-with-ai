# 2장. Claude가 제대로 만들었는지 확인합니다

## 이 장에서 만드는 것

이 장을 끝내면 1장에서 만든 보고서 옆에 두 가지가 더 생깁니다.

| 만들어지는 것 | 무엇인가 |
|---|---|
| source/kobis-2024-source.xlsx | 보고서를 만들 때 사용한 KOBIS 데이터를 작업 당시 상태로 남긴 기준 자료 |
| tests 폴더 | 보고서가 그 기준 자료와 어긋나지 않았는지 언제든 다시 확인하는 자동 검사 |

핵심은 「Claude가 완료했다고 말한 것」과 「우리가 정한 조건을 실제로 만족한 것」을
구분하는 일입니다. 그래서 먼저 완료 조건을 정하고, 그 조건을 기계가 반복해서
확인하게 만듭니다.

검사 항목의 개수는 실행할 때마다 다릅니다. 저자가 두 번 돌렸을 때 7개와 8개가
나왔습니다. 여러분의 개수가 이와 달라도 괜찮습니다. 정한 조건이 모두 들어 있고
실패한 항목이 없으면 제대로 된 것입니다.

## 프롬프트

[prompts.md](prompts.md)에 2장에서 Claude Code에 입력하는 문장이 책의 순서대로
있습니다.

## 장별 Source

[source/movie-report/](source/movie-report/)에는 2장까지 만든 것이 모두 들어 있습니다.
보고서를 만드는 코드, 기준 자료, 자동 검사가 함께 있어 이 폴더 하나만 받아도 바로
실행됩니다. 실습이 잘 진행되는 동안 먼저 열어보는 정답지가 아니라, 아래 복구 방법으로도
해결하지 못했을 때 다음 장부터 이어가기 위한 마지막 수단입니다.

## 검증 결과

저자는 서로 독립된 빈 폴더에서 1장 도착점을 다시 만든 뒤 2장을 이어서 두 번 돌렸습니다.
두 번 모두 기준 자료가 만들어지고 자동 검사가 전항목 통과했습니다. 보고서의 TOP 20
영화명·관객수·매출액은 두 번 모두 기준 자료와 전건 일치했습니다. 근거는
[verification/chapter-02/](../../verification/chapter-02/)에 있습니다.

## 막혔을 때

```text
디버깅 → 내 정상 기록으로 복구 → 장별 Source로 재시작
```

Git 명령을 외우거나 직접 입력할 필요는 없습니다. 아래 요청문을 그대로 붙여넣으면
Claude Code가 확인하고 처리합니다.

**1. 디버깅** — 먼저 무엇이 어긋났는지 그대로 말하고 고쳐봅니다. 대부분 여기서
해결됩니다.

```text
지금 작업이 책과 다르게 진행됐어.
현재 상태와 화면에 나온 문제를 확인하고 원인을 찾아서 고쳐줘.
```

검사가 실패했을 때는 실패한 항목을 그대로 알려주면 됩니다.

```text
자동 검사에서 실패한 항목이 있어. 화면에 나온 내용을 그대로 알려줄게.
기준 자료와 보고서 중 어느 쪽이 잘못됐는지 확인하고 고쳐줘.
```

**2. 내 정상 기록으로 복구** — 해결되지 않으면 실습하면서 내 프로젝트에 남겨둔 정상
기록으로 돌아갑니다. 지금까지 한 작업은 먼저 따로 보존합니다.

```text
현재 작업은 잃지 않도록 먼저 별도로 보존해줘.
이 프로젝트에서 마지막으로 정상 동작했던 상태를 찾아 안전하게 복구해줘.
```

**3. 장별 Source로 재시작** — 그래도 이어갈 수 없을 때 사용합니다. 2장의 남은 실습은
건너뛰게 되므로 마지막 수단입니다.

```text
내 현재 작업을 먼저 안전하게 보존해줘.
아래 2장 완성 Source에서 다시 시작해줘.
https://github.com/buildyourownai-lab/develop-like-a-pro-with-ai/tree/main/chapters/ch02/source/movie-report
준비가 끝나면 2장을 마친 상태인지 확인해줘.
```
