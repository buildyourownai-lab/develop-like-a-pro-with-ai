# 13장: Android·iPhone 확장 계획

이 문서는 아직 앱 코드를 만들기 전에, 무엇을 어디까지 만들지 정한 계획이다.
다음 장(들)에서 Claude가 이 계획을 그대로 꺼내 써서 구현하고 검증한다.

## 1. 앱을 만드는 목적

지금 웹으로만 볼 수 있는 국내 주식 한눈에(시장 현황·종목 검색·종목 상세·차트·공시·
DART 원문·AI 브리핑)을 Android와 iPhone에서도 같은 내용, 같은 기준으로 볼 수 있게
한다. 앱마다 새로운 판단 기준이나 새로운 분석 기능을 추가하는 것이 목적이 아니라,
같은 서버가 계산한 같은 사실을 스마트폰 화면에 맞게 보여주는 것이 목적이다.

## 2. 넣을 기능과 뺄 기능

### 넣는다
- 시장 현황(코스피·코스닥 지수, 상승률 상위·하락률 상위, 검색)
- 종목 검색(종목명/종목코드)
- 종목 상세(현재가, 기준가 대비 등락, 시가·고가·저가, 거래량·거래대금, 기준일)
- 최근 1년 일별 시세 차트 + 공시 시점 표시
- 최근 공시 목록, 전체 공시(유형별 필터), DART 원문 링크
- AI 브리핑(버튼을 눌렀을 때만 생성, 근거·출처·한계를 나눠서 표시, Gemini 한도 안내)

### 이번에 뺀다 (넣을지 자체를 정하지 않음)
- 로그인/사용자 계정 — 지금 웹 서비스에 계정이 전혀 없다(조사로 확인). 앱에 계정을
  넣을지는 이번 계획의 범위가 아니다.
- 푸시 알림, 관심종목 저장, 오프라인 캐시 등 웹에 없던 새 기능
- 앱 자체의 투자 판단·목표주가·추천 기능 — 웹과 마찬가지로 만들지 않는다. 이 원칙은
  플랫폼이 늘어나도 바뀌지 않는다.

## 3. 스마트폰 화면에서 중요한 순서

작은 화면에서는 한 화면에 모든 정보를 동시에 보여줄 수 없으므로 아래 순서를 기본
우선순위로 둔다. 실제 화면 구성(스크롤/탭/카드 배치 등)은 구현 단계에서 정한다.

1. 종목의 현재가와 등락(가장 먼저, 가장 크게)
2. 기준일 — 지수 기준일과 종목 기준일이 다를 수 있다는 사실을 웹처럼 반드시 함께 보여준다
3. 시가·고가·저가·거래량 등 상세 시세
4. 차트(최근 1년)
5. 최근 공시 + DART 원문으로 가는 길
6. AI 브리핑(버튼을 눌러야 생성 — 화면에 들어가자마자 자동으로 만들지 않는다)

## 4. 기존 서버 재사용

- 금융위원회 시세·지수 조회, KRX 상장종목 조회, OpenDART 공시 조회, Gemini 브리핑
  생성·검증, Supabase(DB), Upstash(Cache)는 앱마다 새로 구현하지 않는다. 지금
  `src/lib`에 있는 서버 전용 로직(`stock-price-api.ts`, `market-index-api.ts`,
  `krx-listed-info-api.ts`, `dart-disclosure-api.ts`, `dart-corp-code.ts`,
  `briefing-facts.ts`, `gemini-briefing-api.ts`, `briefing-verify.ts`,
  `briefing-cache.ts`, `gemini-rate-limit.ts`, `db.ts`, `redis.ts`)를 그대로 재사용한다.
- 지금 이 프로젝트는 화면(RSC)이 서버 함수를 직접 부르거나, AI 브리핑 버튼만 서버
  액션(`briefing-actions.ts`)으로 되어 있다. 이 두 방식 모두 앱이 직접 부를 수 있는
  형태가 아니므로, 위 서버 로직을 감싸는 HTTP API 경계를 하나 새로 두고 웹과 앱이
  함께 그 경계를 쓰는 방향으로 간다.
- 가격의 기준일·단위(원/주/%), DART 원문 주소(`dartUrl`), AI 브리핑의 근거
  (`BriefingFacts`)·출처 문구·한계(`unknownCaveats`)·Gemini 한도 상태는 웹과
  앱이 같은 값을 같은 의미로 받아야 한다 — API 경계에서 이 값들을 가공하거나
  합치지 않고 그대로 전달한다.

## 5. Secret·개인정보·기기 권한

- 공공데이터포털 인증키, OpenDART 인증키, Gemini API Key, Supabase 연결 문자열,
  Upstash URL·토큰은 지금처럼 서버에만 두고 앱에는 절대 내려주지 않는다
  (`server-env.ts`가 이미 `server-only`로 지키고 있는 경계를 그대로 유지).
- 오류 메시지에 연결 문자열 등이 섞이지 않게 하는 redaction(`redact.ts`)도 API
  응답에 그대로 적용한다.
- 이 서비스는 사용자 계정·개인정보를 다루지 않는다. 앱 단계에서도 새로 개인정보를
  수집하지 않는 것을 기본값으로 한다.
- 기기 권한은 원칙적으로 최소화한다. DART 원문을 앱 밖 브라우저로 열면 별도 권한이
  필요 없고, 인앱 웹뷰로 열지는 구현 단계 선택 사항이다. 이 계획 시점에는 카메라·
  위치·연락처 등 앱 기능과 무관한 권한을 요청할 이유가 없다.

## 6. 공통 완료 조건

플랫폼과 관계없이 앱이 이 조건을 만족해야 "완료"로 본다.

- 종목 화면에서 AI 브리핑은 버튼을 눌렀을 때만 생성된다(자동 생성하지 않는다).
- 프로그램이 계산한 사실(가격·등락·기간 최고/최저·공시 건수)과 AI가 만든 설명이
  화면에서 분리되어 보인다.
- 이 자료로 알 수 없는 것(투자 판단·목표주가·미래 예측 등)이 목록으로 표시되고,
  AI 브리핑에 투자 추천·목표주가·미래 예측이 나오지 않는다.
- 사용한 출처와 기준일이 함께 보이고, 공시에서 DART 원문으로 내려갈 수 있다.
- 지수 기준일과 종목 기준일이 다르면 그 사실이 화면에 보인다.
- Gemini 호출이 실패하거나 한도에 걸려도 가격·차트·공시는 그대로 보인다.
- 인증키·DB·Cache 연결 정보가 앱 번들, 네트워크 응답, 오류 화면 어디에도 나오지
  않는다.

## 7. 이번에 검증하지 않을 범위

아래는 이번 13장 계획 수립에서 다루지 않았고, 다음 장에서 구현하며 결정·검증할
항목이다.

- 내부 API의 정확한 경로 구조, 요청/응답 스키마, 파일 구성
- Android/iPhone 각각의 기술 스택(네이티브 vs 크로스플랫폼 등) 선택
- 네이티브 차트 컴포넌트 선택과 실제 렌더링
- API 경계에 대한 요청 빈도 제한(rate limit)·인증(앱 식별) 방식
- 실제 기기/시뮬레이터에서의 동작 확인, 스토어 배포 관련 절차
- 오프라인 상태, 저사양 기기, 다양한 화면 크기에서의 실제 동작

## 8. 기존 구현과의 모순 확인

계획을 정리하며 프로젝트를 다시 조사했다. 조사 결과 기존 코드와 모순되는 내용은
찾지 못했다:

- HTTP API(`route.ts`)가 없다는 점, 서버 액션은 AI 브리핑 하나뿐이라는 점을
  실제 파일 구조로 확인했다.
- 로그인/계정 기능이 없다는 점을 `auth`/`login`/`session`/`cookie` 키워드로
  전체 검색해 확인했다.
- 인증키가 서버에만 있다는 점을 `server-env.ts`·`.env.local.example`로 확인했다.
- Android/iOS 관련 파일이나 설정이 프로젝트 안에 아직 전혀 없다는 점을 확인했다
  (이번이 첫 확장 계획이라는 전제와 일치).
