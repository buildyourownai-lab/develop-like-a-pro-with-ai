# YouTube Shorts Production

입력: `$ARGUMENTS`

이 Skill은 한 번에 영상을 뽑는 명령이 아니다. 아래 단계의 산출물을 순서대로 만들고,
사람 승인이 필요한 지점에서 반드시 멈추는 제작 절차다. 새 작업은 별도
`artifacts/<작업명>/` 폴더를 사용하며 기존 완성본을 덮어쓰지 않는다.

## 고정 순서

| 단계 | 먼저 만드는 것 | 다음 단계로 가는 조건 |
|---:|---|---|
| 1 | 소재 후보 3개와 비교표 | 사람이 소재 하나 승인 |
| 2 | 원 논문·연구기관 해설 조사와 50초대 시나리오 | 사실·과장 표현 검사와 사람 승인 |
| 3 | 장면별 화면·내레이션·자막·이미지 설명·움직임 설명 | 사람이 장면 구성표와 화풍 승인 |
| 4 | Kling의 현재 요금제·권리·모델·크레딧 조건과 사용 예산 | 사람이 Kling 유료 단일 제작과 예산을 승인 |
| 5 | 기준 이미지 계획과 예상 크레딧 | 사람이 크레딧 사용 승인 |
| 6 | 기준 이미지 비교 화면 | 사람이 사용할 이미지 승인 |
| 7 | 영상 후보 계획과 예상 크레딧 | 사람이 크레딧 사용 승인 |
| 8 | 영상 후보 비교와 장면별 선택안 | 사람이 최종 장면 승인 |
| 9 | 현재 대본 검사와 음성·음악·효과음 | 검사 통과 뒤 사람이 소리 파일과 기록 승인 |
| 10 | 자막과 영상 조립 결과 | MP4·시나리오·장면 구성표·출처·권리·측정값 반환 |

승인 메시지가 오기 전에는 다음 단계로 넘어가지 않는다. “좋다”, “이게 낫다”처럼
대상과 행동이 불명확한 말은 승인으로 추정하지 않는다.

## 입력과 기본값

- 사용자가 말한 주제, 길이, 화풍, Voice, 음악, 자막 조건만 우선 적용한다.
- 생략한 값은 검증된 Roman Golden Path를 참고해 제안하되 승인 없이 확정하지 않는다.
- 기본 길이는 50~55초, 화면은 1080×1920 세로 H.264/AAC다.
- 이미지와 영상은 Kling 유료 생성으로만 만든다. 다른 영상 서비스로 장면을 채우거나
  섞지 않는다. 음성(Gemini TTS)과 음악(YouTube 오디오 보관함 Pulsar)은 영상 서비스가
  아니며, 각자의 인증과 권리 기록을 따로 유지한다.
- Roman Kling 단일 제작본의 기준 이미지는 Kling에서 장면마다 한 장씩 만든다. 기존
  무료 기준 이미지는 재사용 권리를 확인하지 못하면 쓰지 않고 새로 만든다. 영상은
  장면 1·3·4·5·6에 장면마다 Kling 클립 하나씩, 장면 2·7은 승인한 기준 이미지의
  느린 확대를 사용한다.
- 작업 폴더는 `artifacts/science-roman-concrete-kling-20261012/`, 최종 파일명은
  `roman-concrete-kling-v2.mp4`다. 이전 폴더와 파일은 건드리지 않는다.
- 짧은 생성 영상은 처음부터 반복하지 않는다. 장면 길이에 맞게 조금 느리게 하거나
  마지막 화면을 유지한다. 2배를 넘게 늘려야 하면 조립이 중단되므로 더 긴 클립을 고른다.
- 사용자에게 JSON, 내부 파라미터, Script 이름을 외우게 하지 않는다. Claude가 자연어
  요청을 작업 파일로 옮긴다.

## 대본 Gate

TTS보다 먼저 `script-review.json`을 만든다. 다음 다섯 항목이 모두 `true`이고,
`status`가 `PASS`이며, 출처와 검수자 기록이 있고, 현재 Storyboard·내레이션의
SHA-256이 기록과 같아야 한다.

1. 맞춤법·띄어쓰기·누락
2. 숫자·단위·용어
3. 내레이션·자막 의미 일치
4. 사실
5. 출처

하나라도 다르면 Secret을 읽거나 TTS API를 호출하지 않는다. 대본이나 Storyboard가
바뀌면 이전 음성 Cache를 폐기하고 다시 검수한다.

Roman 기준 실행은 다음 순서다. `review`가 만드는 `script-review.json`은
`REVIEW_REQUIRED` 서식일 뿐이며 자동으로 PASS가 되지 않는다. 실제로 사람 또는 AI가
대본을 읽고 확인한 내용은 PASS 승인과 별도로 기록한다.

```bash
python3 scripts/make_roman_concrete_short.py init
python3 scripts/make_roman_concrete_short.py review
# script-review.json의 다섯 항목·출처·검수자와 Digest를 확인해 PASS 승인
python3 scripts/make_roman_concrete_short.py voice   # 또는 저자가 승인한 외부 Charon 음성이면 import-voice
# 생성한 일곱 음성을 듣고 승인
python3 scripts/make_roman_concrete_short.py all
```

## 생성·비용·권리 확인

- 기준 이미지를 먼저 보여주고 장면 중복, 현대 물건, 의미 없는 글자, 기형 형태,
  자막 공간을 확인한다.
- 실행하는 날 Kling 공식 화면에서 적용 요금제, 남은 크레딧, 모델별 생성 길이·해상도,
  워터마크, 다운로드와 상업 이용 조건을 확인해 기록한다. 명시되지 않은 권리는 추정하지 않는다.
- 크레딧 사용 전 사람 승인을 받는다. 승인한 재시도 상한과 예산 안에서만 생성하고,
  자동 추가 결제, 요금제 업그레이드, 새 Secret·OAuth가 필요하면 멈춘다.
- 선택한 모든 장면 자산은 `assets-manifest.json`에 장면·파일·서비스·요금제·모델·생성 시각·
  약관 URL·약관 확인 시각·권리 근거를 남긴다. 기록이 비었거나 선택한 파일이 없으면
  조립은 성공 대신 중단 메시지를 낸다. 없는 클립을 기준 이미지나 다른 서비스로 대신하지 않는다.
- 화면은 생성형 시각화임을 밝히고, 출처 자료의 그림·문장을 복제하지 않는다.
- BGM은 권리 조건이 확인된 파일만 사용하고 곡명·아티스트·출처를 기록한다.
- Roman 효과음은 선택한 Kling 클립에 원래 소리가 있고 manifest에서
  `native_audio_approved`를 `true`로 승인하고 효과음 권리 기록(`native_audio_rights_basis`,
  `native_audio_reviewed_by`, `native_audio_reviewed_at`)을 남긴 장면에서만, 장면에 맞는 주변음을 사용한다.
  생성된 음악·사람 목소리는 버린다. 클립에 소리가 없으면 그 장면은 무음으로 두고
  `build-report.json`에 남긴다. 다른 출처의 소리로 채우지 않는다. 장면 2·7은 무음이다.
  내레이션 중에는 효과음과 BGM을 낮춘다.
- 배경음악은 항상 Pulsar — The Grey Room / Density & Time이다. manifest의 곡·아티스트·
  출처·라이선스 문구·다운로드 시각과 실제 `pulsar.mp3`의 SHA-256이 모두 맞아야 하며,
  다른 곡으로 대체하지 않는다. 음성은 Gemini Charon이어야 한다.
- 음성 재사용은 파일 이름이 아니라 `tts-cache.json`에 기록한 현재 내레이션 Digest·모델·Voice·
  프롬프트·WAV 해시가 모두 맞을 때만 한다. 저자가 승인해 외부(예: Google AI Studio)에서
  만든 Charon 음성은 `source/audio/voice-import.json`에 출처·모델·생성 시각·검증자·권리
  근거를 적고 `import-voice`로 등록한다. 값을 대신 만들어 넣지 않는다.
- 대본이 바뀌어 검수나 음성이 무효가 되면 이전 검수 기록과 유료 음성을 삭제하지 않고
  `archive/`로 옮긴다.
- 조립 전에 모든 선택 자산이 실제로 열리고 디코딩되는지, SHA-256이 manifest와 같은지,
  장면 1~7이 정확히 한 번씩 순서대로 있는지, 글꼴과 FFmpeg `drawtext`가 되는지 유료 TTS
  호출 전에 검사한다. 완성본은 스테이징에서 검사한 뒤 덮어쓰기 없이 게시한다.
- Gemini API 키 또는 Pulsar 파일이 없으면 다른 음성·음악 서비스로 바꾸지 않고 멈춰
  필요한 항목을 알린다.

## 제작 완료 조건

제작 단계의 출력은 다음 여섯 가지다.

1. 최종 MP4 경로와 SHA-256
2. 최종 시나리오와 장면 구성표
3. `script-review.json`
4. 사용한 생성 결과와 권리 확인 기록
5. 길이·해상도·화면비·영상·음성 형식·음량·검은 화면·전체 읽기 측정값
6. 사람이 직접 볼 항목: 장면 누락·중복, 흔들림, 형태 변형, 자막 오타, 화면과
   내레이션 일치, 목소리·효과음·음악 균형

제작은 MP4와 기록 반환에서 끝난다. MP4를 만들었다고 `UPLOAD READY`라고 쓰지 않는다. 독립 판정은
`video-upload-review`, YouTube 업로드는 `youtube-publisher`가 담당한다.

## 범위 밖

- YouTube 업로드·공개 상태 변경·댓글 작업
- Reviewer를 대신한 합격 판정
- 결제 실행, 유료 Plan 전환, 자동 추가 결제
- 20장 이후의 성과 Evidence·경영 보고 Schema

## 화면 지시와 프롬프트 자체 리뷰

구도·대상별 색상·재료 질감·광원 방향·초점·카메라를 명시한다. 움직임은 시작 상태·변화 위치와 방향·종료 상태·시간 구간으로 나눈다. 대본과 의미가 일치하는지, 고정 카메라와 이동 요구가 충돌하는지, 물이 유색·점성으로 보이는지, 고체가 액체처럼 변하는지 생성 전에 자체 리뷰한다. 과학 장면은 설명용 AI 시각화와 시간 압축을 표시한다. 실제 생성 결과의 형태·동작·소리는 별도로 검사한다. 승인한 배치 안에서 동일 허락을 반복하지 않는다. 명확한 기존 사용자 승인 범위를 존중한다.
