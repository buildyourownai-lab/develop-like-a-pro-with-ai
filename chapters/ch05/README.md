# 5장. 잘되던 때로 돌아갈 곳을 만들어둡니다

## 이 장에서 만드는 것

방금 한 변경을 빠르게 되돌리는 방법과, 오래 남길 정상 상태를 기록하고 컴퓨터
밖에도 보관하는 방법을 만듭니다. movie-report 프로젝트의 마지막 장입니다.

| 방법 | 무엇을 되돌리는가 |
|---|---|
| Checkpointing | Claude Code 안에서 방금 한 변경만 빠르게 |
| Git | 확인한 정상 상태를 기록하고, 필요한 파일만 선택해서 |
| GitHub | 컴퓨터 밖에도 프로젝트와 기록을 보관 |
| Plan mode | 영향이 큰 변경을 실행하기 전에 먼저 계획만 확인 |

끝나면 공통 ~/.claude/CLAUDE.md에 "주요 작업이 끝나면 정상 상태를 기록한다"와 "새
프로젝트는 기록할 곳부터 확인한다"는 원칙이 추가되어, 다음부터는 매번 요청하지 않아도
Claude가 그 순서를 따릅니다.

## 프롬프트

[prompts.md](prompts.md)에 5장에서 Claude Code에 입력하는 문장이 책의 순서대로
있습니다.

## 장별 Source

[source/movie-report/](source/movie-report/)에 PART 1(1~5장) 전체를 끝낸 완성
상태가 있습니다. movie-report 프로젝트의 마지막 장이므로, 완성된 프로젝트 자체는
[movie-report](https://github.com/buildyourownai-lab/movie-report) 저장소에서도
볼 수 있습니다.

## 검증 결과

저자는 4장 도착점에서 시작해 5장 요청문만으로 2회 돌렸습니다. 두 번 모두 검사 8개
통과를 확인한 뒤 정상 기준을 기록했고, 보고서와 새 메모를 함께 바꾼 다음 보고서만
그 기준으로 되돌리고 메모는 남기는 데까지 갔습니다. 복구한 뒤 검사 8개도 다시 전부
통과했습니다. 근거는 [verification/chapter-05/](../../verification/chapter-05/)에
있습니다.

## 막혔을 때

```text
디버깅 → 내 정상 기록으로 복구 → 장별 Source로 재시작
```

Git 명령을 외우거나 직접 입력할 필요는 없습니다. 아래 요청문을 그대로 붙여넣으면
Claude Code가 확인하고 처리합니다.

**1. 디버깅** — 먼저 무엇이 어긋났는지 그대로 말하고 고쳐봅니다. 대부분 여기서
해결됩니다.

```text
지금 작업이 책과 다르게 진행됐어.
현재 상태와 화면에 나온 문제를 확인하고 원인을 찾아서 고쳐줘.
```

Git으로 정상 상태를 기록하기 전에 확인이 필요하다는 답을 받으면 이렇게 물어봅니다.

```text
Git으로 기록하기 전에 확인이 필요한 게 있다고 나왔어.
무엇을 확인해야 하는지 쉬운 말로 설명해줘.
```

**2. 내 정상 기록으로 복구** — 해결되지 않으면 실습하면서 내 프로젝트에 남겨둔 정상
기록으로 돌아갑니다. 지금까지 한 작업은 먼저 따로 보존합니다.

```text
현재 작업은 잃지 않도록 먼저 별도로 보존해줘.
이 프로젝트에서 마지막으로 정상 동작했던 상태를 찾아 안전하게 복구해줘.
```

**3. 장별 Source로 재시작** — 그래도 이어갈 수 없을 때 사용합니다. movie-report의
마지막 장이므로, 이 수단을 쓰면 PART 1 실습을 마친 것으로 보고 6장으로 넘어가면
됩니다.

```text
내 현재 작업을 먼저 안전하게 보존해줘.
아래 5장 완성 Source에서 다시 시작해줘.
https://github.com/buildyourownai-lab/develop-like-a-pro-with-ai/tree/main/chapters/ch05/source/movie-report
준비가 끝나면 5장을 마친 상태인지 확인해줘.
```
