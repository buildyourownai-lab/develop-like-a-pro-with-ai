# 문제 발생 시 디버그 절차

`pytest`(`tests/test_movie_report.py`)가 실패하는 등 문제가 생겼을 때 이 순서로 진행한다.
바로 코드를 고치지 않고, 아래 순서를 지켜 원인을 좁힌 뒤에 고친다.

## 1. 고치지 않은 채로 같은 실패를 다시 확인한다

- `build_movie_report.py`나 데이터를 건드리기 전에 `python3 -m pytest -q`를 다시 실행해
  같은 실패가 재현되는지 확인한다.
- 재현되지 않으면(예: 일시적 문제) 그 사실을 기록하고, 재현되는 조건을 먼저 찾는다.

## 2. 보존한 기준 자료부터 값을 차례로 비교해 처음 달라지는 지점을 찾는다

- 이 프로젝트의 기준 자료는 `source/kobis-2024-source.xlsx`(원본데이터 시트)다.
- 비교 순서: `source/kobis-2024-source.xlsx` → `build_movie_report.py`의 `TOP20` 상수 →
  `movie-report-2024.xlsx`(TOP20 시트) → `movie-report-2024.xlsx`(요약/출처 시트).
- 각 단계에서 순위·영화명·관객수·매출액 값을 순서대로 비교해, 값이 처음으로 달라지는
  단계를 찾는다. 그 단계가 원인이 있는 지점이다.

## 3. 확인된 사실과 아직 추측인 것을 나눠 적는다

- "확인된 사실": 실제로 비교해서 다르다고 확인한 값, 실행해서 본 에러 메시지 등.
- "아직 추측": 왜 달라졌는지에 대한 가설(예: "출처 사이트 값이 갱신된 것 같다").
- 두 목록을 분리해서 적어 두고, 추측을 사실처럼 다루지 않는다.

## 4. 증거로 원인을 확인한 뒤 필요한 부분만 고친다

- 3단계의 추측 중 어느 것이 맞는지 증거(파일 값, 로그, 실행 결과)로 확인한다.
- 원인이 확정되면 그 원인에 해당하는 부분만 수정한다. 관련 없는 코드나 값은 함께
  고치지 않는다.

## 5. 실패했던 Test와 기존 Test 전체를 다시 실행한다

- 처음 실패했던 테스트가 통과하는지 확인한다.
- 이어서 `python3 -m pytest -q`로 전체 테스트를 다시 실행해 다른 테스트가 깨지지
  않았는지 확인한다.
- 하나라도 실패하면 완료된 것으로 보지 않고 1단계부터 다시 진행한다.
