# 22장 대화 기능 검증

2026-09-14 확인. 21장은 기획, 22장은 로컬 구현과 실제 자료 확인까지 진행합니다.

## 구현 범위

기존 주식서비스에 대화창과 세 조회 기능을 연결했습니다. 확인된 종목·수치·날짜·출처는 서버 자료로 표시하고, 관련 개념은 `최신 확인 자료가 아닙니다` 표시와 함께 AI 일반 설명으로 보여 줍니다.

- 종목 찾기, 최근 종가·1개월·3개월·1년 가격 요약, 최근 공시 최대 5건.
- 모호한 종목의 후보 선택, 최근 3회 대화, 대상 전환 시 이전 근거 초기화.
- 질문 1,000자, 한 질문의 모델 호출 3회·조회 4회·전체 30초 제한, 중복 전송 방지.
- 대화 기록은 현재 탭 메모리에서만 유지합니다. 기존 자료 Cache는 재사용합니다.

대화 전용 사용량 저장소는 필요하지 않습니다. 22장 완성본은 기본으로 켜지며, `CHAT_ENABLED=false`로 끌 수 있습니다. 공개 사용량 관리 장치를 만드는 실습은 포함하지 않습니다.

## 자동 검사 결과

| 검사 | 명령 | 결과 |
|---|---|---|
| 단위 검사 | `npm test` | 152개 통과 |
| 타입 | `npx tsc --noEmit` | 통과 |
| Lint | `npm run lint` | 통과 |
| 빌드 | `npm run build` | 통과 |
| 대화 켜짐 | `npm run test:chapter22:e2e` | 8개 통과, 꺼짐 전용 2개 제외 |
| 대화 꺼짐 | `npm run test:chapter22:off` | 2개 통과, 켜짐 전용 8개 제외 |

화면 검사는 macOS의 Playwright Chromium으로 실행했습니다. 켜짐 검사는 API 응답을 명시적인 시험 응답으로 대체하므로 실제 AI 답변의 품질 검사가 아닙니다. 꺼짐 검사는 버튼이 없고 API가 404로 끝나는지 확인합니다. 두 명령은 켜짐·꺼짐을 직접 지정하며, 시험 서버의 Gemini 키만 비웁니다. 독자의 환경 파일은 변경하지 않습니다. Windows 실행은 확인하지 않았습니다.

단위 검사는 실제 종목과 근거의 연결, 후보 선택, 요청 기간, 질문당 상한, 자료 없음과 실패의 구분을 확인합니다. `삼성전자의`처럼 조사가 붙은 검색어가 0건이면 질문에 있는 짧은 검색어로 한 번만 다시 조회하는 경우도 검사합니다. 이 조회 역시 같은 횟수·시간 제한을 적용받습니다.

## 실제 API 확인

같은 제품 판본을 분리된 로컬 환경에서 실행하고 본문의 다음 질문을 실제 Gemini와 기존 조회 기능으로 확인했습니다.

- 메인에서 `삼성전자의 최근 공시 5건을 DART 원문과 함께 보여줘.` → 삼성전자(005930), 공시 5건과 원문 링크. 수행 내역은 종목 찾기·공시 조회이며 가격 조회는 없었습니다.
- 삼성전자 상세 문맥에서 `이 종목의 최근 확인 종가와 기준일을 알려주고, 가격을 볼 때 기준일을 확인해야 하는 이유도 설명해줘.` → 최근 종가·기준일과 AI 일반 설명을 분리해 반환했습니다. 기간을 다시 묻지 않았습니다.

위 결과는 실제 API 응답 확인이며 본문 스크린샷 촬영이나 독자 요청문 전체 재현 완료를 뜻하지 않습니다. 데이터와 AI 설명은 조회 시점에 달라질 수 있습니다.
