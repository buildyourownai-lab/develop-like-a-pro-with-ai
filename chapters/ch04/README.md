# 4장. 같은 실수는 두 번 하지 않게 합니다

## 이 장에서 만드는 것

3장에서 찾은 문제 해결 방식을 다음에도 반복해서 지킬 규칙으로 남깁니다. 세 파일이
자리를 잡습니다.

| 위치 | 담기는 것 |
|---|---|
| ~/.claude/CLAUDE.md | 모든 프로젝트에서 참고할 공통 작업 원칙 |
| movie-report/CLAUDE.md | 영화 보고서 프로젝트에서만 참고할 규칙 |
| movie-report/docs/debug-procedure.md | 문제가 생겼을 때 따르는 자세한 확인 절차 |

그다음부터는 제목 변경처럼 작은 요청만 해도 Claude가 공통 작업 원칙을 참고해 관련
Test를 스스로 실행하고 전부 통과를 확인한 뒤 완료를 보고합니다. 세 파일의 소제목과
문장은 실행마다 달라집니다. 기준은 문장이 같은지가 아니라 공통 원칙과 프로젝트 규칙이
중복 없이 나뉘었는지입니다.

## 프롬프트

[prompts.md](prompts.md)에 4장에서 Claude Code에 입력하는 문장이 책의 순서대로
있습니다.

## 장별 Source

[source/movie-report/](source/movie-report/)에 4장을 끝낸 상태가 모두 있습니다. 정상
흐름에서 먼저 열어보는 정답지가 아니라, 아래 복구 방법으로도 해결하지 못했을 때 5장부터
계속 진행하기 위한 마지막 복구 수단입니다. 공통 ~/.claude/CLAUDE.md는 이 프로젝트 안의
파일이 아니므로 여기에 없습니다.

## 검증 결과

저자가 3장 도착점에서 시작해 4장 요청문만으로 두 번 돌렸고, 두 번 모두 두 규칙이 중복
없이 나뉘고 제목 변경만 요청했는데도 Claude가 검사 8개를 스스로 실행해 전부 통과를
확인한 뒤 완료를 보고했습니다. 근거는
[verification/chapter-04/](../../verification/chapter-04/)에 있습니다.

## 막혔을 때

```text
디버깅 → 내 정상 기록으로 복구 → 장별 Source로 재시작
```

Git 명령을 외우거나 직접 입력할 필요는 없습니다. 아래 요청문을 그대로 붙여넣으면
Claude Code가 확인하고 처리합니다.

**1. 디버깅** — 먼저 무엇이 어긋났는지 그대로 말하고 고쳐봅니다. 대부분 여기서
해결됩니다.

```text
지금 작업이 책과 다르게 진행됐어.
현재 상태와 화면에 나온 문제를 확인하고 원인을 찾아서 고쳐줘.
```

이 장에서 특히 자주 막히는 자리는 공통 규칙과 프로젝트 규칙이 뒤섞이는 경우입니다.

```text
~/.claude/CLAUDE.md와 movie-report/CLAUDE.md의 내용이 섞인 것 같아.
모든 프로젝트에서 쓸 원칙과 이 프로젝트에만 필요한 규칙을
다시 나눠서 정리해줘.
```

**2. 내 정상 기록으로 복구** — 해결되지 않으면 실습하면서 내 프로젝트에 남겨둔 정상
기록으로 돌아갑니다. 지금까지 한 작업은 먼저 따로 보존합니다.

```text
현재 작업은 잃지 않도록 먼저 별도로 보존해줘.
이 프로젝트에서 마지막으로 정상 동작했던 상태를 찾아 안전하게 복구해줘.
```

**3. 장별 Source로 재시작** — 그래도 이어갈 수 없을 때 사용합니다. 4장의 남은 실습은
건너뛰게 되므로 마지막 수단입니다.

```text
내 현재 작업을 먼저 안전하게 보존해줘.
아래 4장 완성 Source에서 다시 시작해줘.
https://github.com/buildyourownai-lab/develop-like-a-pro-with-ai/tree/main/chapters/ch04/source/movie-report
준비가 끝나면 4장을 마친 상태인지 확인해줘.
```
