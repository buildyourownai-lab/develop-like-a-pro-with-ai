# getting-started 요청문

책 본문의 요청문 사본입니다. 각 요청문의 상황을 확인한 뒤 사용합니다.

## 처음에는 수동 모드로 시작합니다

~~~prompt
이 작업이 왜 필요한지 쉽게 설명해줘. 아직 실행하지 마.
~~~

## 제대로 열린 폴더인지 확인합니다

~~~prompt
지금은 파일을 만들거나 수정하지 마. 현재 작업 폴더가 이 책에서 여러 프로젝트를 모아둘 develop-like-a-pro-with-ai 폴더가 맞는지 확인해줘. 이 컴퓨터에서 Git도 사용할 수 있는지 확인해줘. 맞다면 첫 번째 프로젝트를 시작할 준비가 되었다고 알려줘.
~~~

## Mac에서 Git이 없다고 나올 때

~~~prompt
이 Mac에 Git이 없다고 나왔어. macOS 개발자 도구를 설치하는 명령을 실행해줘. 설치 창이 뜨면 알려줘.
~~~

## 이 장에서 막혔다면

~~~prompt
Claude Desktop에서 Code 탭을 열고 내 컴퓨터의 폴더를 작업 폴더로 선택하려고 해. 지금 화면에 이렇게 나오는데 다음에 무엇을 눌러야 하는지 알려줘.
~~~

## 먼저 한 번 연결합니다

~~~prompt
Study AI Lab MCP를 지금 열어 둔 작업 폴더에서 사용하도록 연결해줘. 공식 안내는 https://www.studyailab.com/develop/mcp#connect 이고 서버 주소는 https://mcp.studyailab.com 이야.

먼저 현재 AI와 작업 폴더, 기존 MCP 등록을 확인해줘. 같은 공식 주소가 있으면 재사용하고, 같은 이름에 다른 주소가 있으면 덮어쓰지 말고 알려줘.

새 등록이 필요하면 이 작업 폴더에만 적용할 설정과 만들거나 바꿀 파일 목록을 먼저 보여줘. 내가 승인한 뒤에만 연결해줘. 이 범위로 연결할 수 없으면 다른 범위에 임의로 등록하지 말고 차이를 알려줘.

기존 지침, 다른 AI 설정, 실습 코드와 기록을 보존해줘. 별도 튜터나 Skill을 설치하거나 예제 프로그램을 실행하지 마. 개인 파일, 프로젝트 경로, 진도와 인증값을 원격으로 보내지 마.

Python이 없어도 자료 연결은 확인해줘. 등록을 마치면 변경한 내용과 새 대화를 여는 방법을 알려줘. 새 대화에서 실제 자료를 읽기 전에는 학습 기능이 확인됐다고 말하지 마. 막히면 확인한 오류와 다음에 할 일 하나를 알려줘.
~~~

## 준비됐다는 말보다 실제 자료를 봅니다

~~~prompt
Study AI Lab MCP로 개발책 1장의 자료를 확인해줘. 공개 요청문 목록을 찾고, 그중 하나의 본문과 출처·자료 판본을 보여줘. 등록돼 있다는 표시만으로 조회에 성공했다고 말하지 마.

지금 열린 작업 폴더도 확인하고, 자료를 읽은 것과 내 파일이나 실행 결과를 확인한 것을 구분해줘. 아직 확인하지 못한 준비는 그대로 남겨줘. 1장을 시작하려면 다음에 무엇을 할지 한 가지만 알려줘. 지금은 프로그램을 설치하거나 실습 결과물을 만들지 마.
~~~

## 이제 함께 공부할 방식을 정합니다

~~~prompt
이제부터 이 책을 함께 공부할 내 튜터가 되어줘. 만드는 순서는 책을 따라갈게. 막히면 다음에 확인할 것부터 알려줘. 힌트만 부탁했을 때는 파일을 바꾸거나 정답을 먼저 적용하지 마. 낯선 용어는 지금 만드는 것과 연결해서 쉽게 설명해줘.

첫 질문이야. 1장에서 사용할 Python과 openpyxl은 각각 어떤 역할이야? 만들 Excel 보고서와 연결해 세 문장으로 설명해줘. 지금은 파일을 만들거나 프로그램을 설치하지 마.
~~~

## Python 준비 뒤 로컬 점검과 재개를 준비합니다

~~~prompt
1장에서 준비한 Python으로 이 프로젝트의 로컬 점검과 다음 대화 재개를 준비해줘. 먼저 Python을 실제로 사용할 수 있는지 확인해줘. 없다면 설치를 시작하지 말고 로컬 점검은 미실시로 남긴 뒤 1장의 Python 준비로 안내해줘. 공개 자료 조회는 계속 사용할 수 있게 해줘.

공식 안내 https://www.studyailab.com/develop/mcp#support-files 에서 지원 파일의 받을 위치·판본·무결성 확인 방법을 읽어줘. 확인할 수 없거나 파일 검증에 실패하면 실행하지 말고 원인과 다음 행동 하나를 알려줘.

현재 폴더 안에서 만들거나 바꿀 파일과 사용할 지원 도구를 먼저 보여주고, 내가 승인한 뒤에만 준비해줘. 기존 프로젝트 지침과 코드·작업 기록을 덮어쓰지 말고, 별도 튜터나 Skill을 설치하지 마. 개인 파일과 진도·인증값은 원격으로 보내지 마.

점검은 내가 허용한 파일과 실행 결과를 근거로 해줘. 현재 장·확인한 것·미확인·다음 행동을 내 컴퓨터에 남기고, 새 대화에서 장과 폴더를 확인한 뒤 실제 파일 상태를 다시 점검하는 방법을 알려줘. 확인하지 않은 결과를 완료로 기록하거나 실습 프로그램을 미리 만들지 마.
~~~
