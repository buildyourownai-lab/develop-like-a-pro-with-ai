## P20-05 · 같은 댓글에 두 번 답하지 않게 합니다

~~~prompt
채널·영상·원래 댓글 ID를 묶어 같은 댓글을 두 실행이 동시에 보내지 못하게 해줘.
전송을 맡은 상태를 DB에 먼저 기록하고, 실제 전송 성공 뒤 YouTube가 준 답글 ID를 기록해줘.
예약 전송 직전에는 예약이 켜져 있는지, 수동 전송은 화면에서 새로 승인한 문장인지 확인해줘.
두 경우 모두 결과 미확인으로 중단된 상태가 아닌지와 후보·검사 결과가 유효한지 다시 확인해줘.

전송 요청 뒤 응답을 못 받거나, 성공 뒤 기록 저장에 실패하면 결과 미확인으로 남기고 자동화를 멈춰줘.
전송 중 기록의 잠금 시간이 지났다는 이유만으로 다시 보내지 마.
먼저 해당 원래 댓글의 답글을 실제로 조회해 내 채널의 답글이 있는지 확인해줘.
댓글 목록에 함께 온 답글은 일부일 수 있으니, 그것만 보고 답글이 없다고 결론 내리지 마.
원래 댓글의 답글 목록을 마지막 페이지까지 확인해줘.
확인할 수 없으면 미확인으로 남겨. 자동 재전송하지 마.
해당 댓글에 내 채널의 답글이 이미 있으면 추가로 보내지 마. 그것이 이번 전송인지
확정할 수 없으면 성공으로 바꾸지 않고, 중복 방지를 위해 사람 확인 상태를 유지해.

댓글 원문·작성자·답글 전문은 저장하지 말고 실행에 필요한 ID·상태·시각·이유 코드만 비공개로 보관해줘.
30일이 지난 처리 기록은 삭제하고, 이미 후보 기간인 7일을 벗어난 댓글은 다시 처리하지 마.
권한 철회나 삭제 요청이 있으면 적용 정책을 확인해 더 이르게 정리할 수 있게 해줘.
~~~

## P20-09 · 작은 범위로 예약 실행을 켭니다

~~~prompt
현재 프로젝트에서 예약 실행에 사용하는 Vercel 주소와 인증 방식을 먼저 확인해줘.
Supabase에서 그 주소를 10분마다 부르는 예약 하나를 준비해줘.
주소와 인증값은 안전한 저장소에서 읽고, 인증값을 URL·예약 SQL·로그에 직접 넣지 마.
예약 등록 결과와 서버가 실제 작업을 마친 결과는 별도로 기록해줘.

승인한 영상 한 편에서만, 시작 시각 이후이면서 최근 7일 안의 댓글을 처리하게 해줘.
일반 반응·후속 요청 중 두 검사를 통과한 후보를 순서대로 처리해줘. 회당·하루 전송 개수 제한은 두지 마.
전송 결과가 미확인이면 기록과 중단 상태를 유지하고 자동 재전송하지 마.
영상 소유 채널이 작성한 최상위 댓글은 내용과 관계없이 자동답글과 수동 승인 대상에서 모두 제외해줘.
댓글 작성 채널 ID를 확인할 수 없을 때도 보내지 말고 검토 대상으로 남겨.
후보를 고를 때와 초안을 만들 때, 실제 전송 직전에 영상 소유 채널 ID와 댓글 작성 채널 ID를 다시 대조해줘.
답글·이미 처리한 댓글도 자동 대상에서 제외해줘.
조회·Gemini의 호출량과 전체 실행 시간을 제한하고, API 한도나 인증 오류에서 반복 호출하지 마. 여러 건을 보내다 중지·오류가 나면 멈추고 이미 보낸 건수를 정확히 기록해줘.
같은 감사 문장을 짧은 시간에 여러 댓글에 반복 게시하려는 경우 전송하지 않고 검토 대상으로 남겨.
검사를 피하려고 같은 문장의 표현만 무작위로 바꾸는 기능은 만들지 마.

먼저 시험 실행과 중지 방법까지 확인해줘. 아직 예약과 자동전송은 활성화하지 마.
~~~
