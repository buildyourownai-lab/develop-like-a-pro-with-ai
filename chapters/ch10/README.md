# 10장. 이 회사는 최근 무엇을 공시했을까?

## 이 장에서 만드는 것

10장에서는 9장에서 만든 ai-stock-briefing에 공시를 붙입니다. 금융감독원 전자공시시스템
DART의 OpenDART에서 회사가 직접 제출한 자료를 가져와, 주가 차트와 같은 기간에 회사가
무엇을 발표했는지 한 화면에서 보고 필요하면 DART 원문까지 내려갑니다.

이 장에서 확인하는 것은 여섯 가지입니다.

| 무엇 | 어떻게 확인하나 |
|---|---|
| 최근 공시부터 본다 | 종목 화면에서 최근 공시 5건과 조회 기간, 그 기간의 전체 건수가 함께 보이는지 확인합니다 |
| 수백 건을 나눠 본다 | 전체 공시 화면에서 한 페이지에 100건씩, 페이지를 넘기며 그 기간의 공시를 모두 볼 수 있는지 확인합니다 |
| 공식 유형으로 좁혀 본다 | 정기공시·주요사항보고·지분공시 같은 OpenDART 공식 유형과 각 유형의 실제 건수를 확인합니다 |
| 차트에서 공시 시점을 본다 | 최근 1년 차트에 정기공시와 주요사항보고의 시점만 표시되고, 표식을 눌러 접수일과 보고서명을 확인합니다 |
| 원문까지 내려간다 | 보고서명을 눌러 실제 DART 원문이 새 창에서 열리는지 확인합니다 |
| 0건과 실패를 구분한다 | 공시가 없는 경우와 OpenDART 요청이 실패한 경우가 화면에서 다르게 표시되는지 확인합니다 |

공시는 계속 새로 접수되므로 화면의 건수는 실행하는 날에 따라 달라집니다. 완료 기준은
건수가 같은지가 아니라, 공시 목록의 조회 기간이 주가 차트와 같은지와 그 기간에서 빠진
공시가 없는지입니다.

## 프롬프트

## 장별 Source

[source/ai-stock-briefing/](source/ai-stock-briefing/)에 10장을 끝낸 상태가 있습니다.
9장까지 만든 파일이 모두 들어 있어 이 폴더만 받아도 자기 컴퓨터에서 돌릴 수 있습니다.

정상 흐름에서 먼저 열어보는 정답지가 아닙니다. 아래 복구 방법으로도 이어갈 수 없을 때
11장부터 계속 진행하기 위한 마지막 수단입니다.

## 검증 결과

저자는 9장을 끝낸 상태에서 10장 요청문만으로 최근 공시와 전체 공시, 공식 유형, 차트의
공시 시점, DART 원문까지 갔습니다. 프로젝트 전체 Test 48개가 통과했고 그중 25개가 이
장에서 새로 생겼습니다. 실제 OpenDART 응답에서 SK하이닉스의 최근 1년 공시 477건을
확인하고, 이 건수가 100건씩 5페이지로 나뉘는 것과 공식 유형별 건수의 합이 전체 건수와
같은 것도 확인했습니다. 근거는
[verification/chapter-10/](../../verification/chapter-10/)에 있습니다.

## 막혔을 때

```text
디버깅 → 내 정상 기록으로 복구 → 장별 Source로 재시작
```

Git 명령을 외우거나 직접 입력할 필요는 없습니다. 아래 요청문을 그대로 붙여넣으면
Claude Code가 확인하고 처리합니다.

**1. 디버깅** --- 먼저 무엇이 어긋났는지 그대로 말하고 고쳐봅니다. 대부분 여기서
해결됩니다.

```text
지금 작업이 책과 다르게 진행됐어.
현재 상태와 화면에 나온 문제를 확인하고 원인을 찾아서 고쳐줘.
```

공시 조회가 되지 않을 때는 인증키 문제와 조회 결과가 0건인 것을 먼저 갈라야 합니다.
OpenDART는 이 둘을 서로 다른 상태 코드로 알려줍니다.

```text
공시 조회가 안 돼.
OpenDART가 돌려준 상태 코드를 확인해서 결과가 0건인 경우와 실제 오류를 구분해줘.
실제 인증키 값은 출력하지 마.
```

주가 차트와 공시 목록의 기간이 어긋나면 같은 화면에서 두 자료를 나란히 읽을 수 없습니다.

```text
주가 차트와 공시 목록의 조회 기간이 서로 달라.
두 화면이 같은 최근 1년을 조회하고 있는지 확인해서 맞춰줘.
```

종목코드로 회사를 찾지 못하는 경우도 있습니다. OpenDART는 주식 화면의 종목코드와 다른
고유번호를 사용합니다.

```text
종목코드로 OpenDART 회사를 찾지 못해.
OpenDART 회사 고유번호 자료를 기준으로 종목코드와 고유번호가 연결되는지 확인해줘.
```

**2. 내 정상 기록으로 복구** --- 해결되지 않으면 실습하면서 내 프로젝트에 남겨둔 정상
기록으로 돌아갑니다. 지금까지 한 작업은 먼저 따로 보존합니다.

```text
현재 작업은 잃지 않도록 먼저 별도로 보존해줘.
이 프로젝트에서 마지막으로 정상 동작했던 상태를 찾아 안전하게 복구해줘.
```

**3. 장별 Source로 재시작** --- 그래도 이어갈 수 없을 때 사용합니다. 10장의 남은 실습은
건너뛰게 되므로 마지막 수단입니다.

```text
내 현재 작업을 먼저 안전하게 보존해줘.
아래 10장 완성 Source에서 다시 시작해줘.
https://github.com/buildyourownai-lab/develop-like-a-pro-with-ai/tree/main/chapters/ch10/source/ai-stock-briefing
내 인증키를 입력할 자리를 알려주고
준비가 끝나면 10장을 마친 상태인지 확인해줘.
```
