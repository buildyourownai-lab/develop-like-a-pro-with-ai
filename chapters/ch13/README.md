# 13장. 웹서비스를 앱으로 만들기 전에 알아야 할 것들

## 이 장에서 만드는 것

13장에서는 앱 코드를 만들지 않습니다. 12장까지 만든 ai-stock-briefing을 Android와
iPhone으로 확장하기 전에, 무엇을 어디까지 만들지 사람이 먼저 정합니다. 이 장의 결과물은
다음 두 장에서 그대로 꺼내 쓰는 계획 문서입니다.

이 장에서 확인하는 것은 다섯 가지입니다.

| 무엇 | 어떻게 확인하나 |
|---|---|
| 기존 서비스에서 무엇을 재사용할지 안다 | 화면은 새로 만들고 주식 데이터·공시·AI 브리핑은 기존 서버를 쓴다고 갈라져 있는지 확인합니다 |
| 첫 앱의 범위가 정해졌다 | 넣을 기능과 뺄 기능이 각각 적혀 있는지 확인합니다 |
| Secret은 앱에 들어가지 않는다 | 앱에 넣지 않을 값이 목록으로 적혀 있는지 확인합니다 |
| 완료 조건이 사람의 사용 흐름으로 적혔다 | 기술 이름이 아니라 앱을 열어 무엇을 할 수 있으면 완성인지로 적혀 있는지 확인합니다 |
| 계획이 실제 구현과 어긋나지 않는다 | 없는 기능을 있다고 적지 않았고 제외한 기능을 다른 곳에서 전제하지 않는지 확인합니다 |

계획 문서의 파일 이름과 문장은 매번 달라집니다. 완료 기준은 책과 같은 문서가 나오는 것이
아니라, 위 다섯 가지가 다음 장으로 넘어갈 수 있는 상태로 정해지는 것입니다.

## 프롬프트

[prompts.md](prompts.md)에 13장에서 Claude Code에 입력하는 문장이 책의 순서대로 있습니다.

## 장별 Source

[source/ai-stock-briefing/](source/ai-stock-briefing/)에 13장을 끝낸 상태가 있습니다.
9장부터 13장까지 만든 파일이 모두 들어 있어 이 폴더만 받아도 자기 컴퓨터에서 돌릴 수
있습니다. 12장 상태와 비교하면 docs/mobile-app-plan.md 계획 문서가 더해졌고 코드는
같습니다.

정상 흐름에서 먼저 열어보는 정답지가 아닙니다. 아래 복구 방법으로도 이어갈 수 없을 때
14장부터 계속 진행하기 위한 마지막 수단입니다.

## 검증 결과

저자는 12장을 끝낸 상태에서 13장 요청문만으로 계획 문서까지 갔습니다. 계획에는 목적,
넣을 기능과 뺄 기능, 작은 화면에서 중요한 순서, 기존 서버 재사용, 앱에 넣지 않을 Secret과
요청하지 않을 기기 권한, Android와 iPhone 공통 완료 조건, 이번에 검증하지 않을 범위가
모두 들어갔고, 기존 구현과 모순되는 내용은 없었습니다. 마지막 요청문까지 실행하면 계획
문서가 Git 기록에 남고 작업 폴더가 깨끗해지는 것도 확인했습니다. 이 장은 코드를 바꾸지
않으므로 새로 생긴 Test는 없고, Source 안의 Test는 12장과 같은 113개입니다. 근거는
[verification/chapter-13/](../../verification/chapter-13/)에 있습니다.

## 막혔을 때

```text
디버깅 → 내 정상 기록으로 복구 → 장별 Source로 재시작
```

Git 명령을 외우거나 직접 입력할 필요는 없습니다. 아래 요청문을 그대로 붙여넣으면
Claude Code가 확인하고 처리합니다.

**1. 디버깅** --- 먼저 무엇이 어긋났는지 그대로 말하고 고쳐봅니다. 대부분 여기서
해결됩니다.

```text
지금 작업이 책과 다르게 진행됐어.
현재 상태와 화면에 나온 문제를 확인하고 원인을 찾아서 고쳐줘.
```

이 장에서 Claude가 앱 코드를 만들기 시작했다면 범위를 벗어난 것입니다.

```text
이번 장에서는 앱 코드를 만들지 않고 계획만 정하는 거야.
지금까지 만든 것 가운데 계획이 아닌 것이 있으면 알려주고 되돌려줘.
```

계획 문서에 무엇이 빠졌는지 모를 때는 항목별로 확인하게 합니다.

```text
지금 계획 문서에 목적, 넣을 기능과 뺄 기능, 화면 순서, 기존 서버 재사용,
Secret과 개인정보와 기기 권한, 공통 완료 조건, 검증하지 않을 범위가
각각 들어 있는지 하나씩 확인해서 알려줘. 빠진 것만 보태줘.
```

계획이 기존 서비스와 어긋난 것 같으면 다시 대조하게 합니다.

```text
계획을 현재 프로젝트와 다시 대조해줘.
없는 기능을 이미 있다고 쓴 곳, 제외한 기능을 전제한 곳,
Secret이 앱으로 들어가는 방향이 있는지 확인해서 계획만 바로잡아줘.
```

**2. 내 정상 기록으로 복구** --- 해결되지 않으면 실습하면서 내 프로젝트에 남겨둔 정상
기록으로 돌아갑니다. 지금까지 한 작업은 먼저 따로 보존합니다.

```text
현재 작업은 잃지 않도록 먼저 별도로 보존해줘.
이 프로젝트에서 마지막으로 정상 동작했던 상태를 찾아 안전하게 복구해줘.
```

**3. 장별 Source로 재시작** --- 그래도 이어갈 수 없을 때 사용합니다. 13장의 남은 실습은
건너뛰게 되므로 마지막 수단입니다.

```text
내 현재 작업을 먼저 안전하게 보존해줘.
아래 13장 완성 Source에서 다시 시작해줘.
https://github.com/buildyourownai-lab/develop-like-a-pro-with-ai/tree/main/chapters/ch13/source/ai-stock-briefing
내 인증키와 Database, Cache 접속 정보를 입력할 자리를 알려주고
준비가 끝나면 13장을 마친 상태인지 확인해줘.
```
