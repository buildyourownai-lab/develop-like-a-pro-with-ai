# 3장. 문제가 생기면, 고치기 전에 원인부터 찾습니다

## 이 장에서 만드는 것

이 장은 새 파일을 만들지 않습니다. 만드는 것은 **절차**입니다.

2장에서 만든 정상 보고서에 오류를 하나 일부러 넣고, 다음 순서로 원인을 찾아 되돌립니다.

| 순서 | 무엇을 하는가 |
|---|---|
| 1 | 같은 조건에서 문제가 다시 나타나는지 확인합니다 |
| 2 | 보존한 기준 자료부터 최종 요약까지 값을 차례로 비교합니다 |
| 3 | 처음 값이 달라지는 지점을 찾습니다 |
| 4 | 확인된 사실과 아직 추측인 것을 나눕니다 |
| 5 | 증거로 근본 원인을 확인한 뒤 그 부분만 고칩니다 |
| 6 | 실패했던 검사와 기존 검사 전체를 다시 실행합니다 |

끝내면 보고서와 기준 자료는 3장을 시작하기 전 상태로 돌아오고 검사도 다시 전부
통과합니다. 코드나 Excel 계산식을 읽지 않고 여기까지 갑니다.

실패한 검사가 몇 개인지는 실행할 때마다 다릅니다. 저자가 두 번 돌렸을 때 한 번은 2개,
한 번은 1개가 실패했습니다. 한 곳을 고쳤는데 실패가 여러 개일 수 있습니다. 평균처럼
그 합계를 다시 쓰는 값이 함께 실패하기 때문입니다.

## 프롬프트

[prompts.md](prompts.md)에 3장에서 Claude Code에 입력하는 문장이 책의 순서대로
있습니다.

## 장별 Source

이 장은 파일을 새로 만들지 않으므로 별도의 source 폴더를 두지 않았습니다. 3장을 끝낸
상태는 2장을 끝낸 상태와 같습니다. 마지막 복구 수단이 필요하면
[ch02/source/movie-report/](../ch02/source/movie-report/)를 사용하세요. 정상 흐름에서
먼저 열어보는 정답지가 아니라, 아래 복구 방법으로도 해결하지 못했을 때 다음 장부터
이어가기 위한 마지막 수단입니다.

## 검증 결과

저자는 빈 폴더에서 1·2장을 다시 만든 뒤 3장을 이어서 2회 돌렸습니다. 두 번 모두
합계 검사가 실패했고, 최초로 값이 달라지는 지점이 상세 데이터에서 요약으로 넘어가는
곳이었으며, 두 합계의 차이가 20위 영화 한 편의 관객수와 정확히 같았습니다. 한 줄만
고친 뒤 두 번 모두 기존 검사가 전부 통과했습니다. 근거는
[verification/chapter-03/](../../verification/chapter-03/)에 있습니다.

## 막혔을 때

```text
디버깅 → 내 정상 기록으로 복구 → 장별 Source로 재시작
```

Git 명령을 외우거나 직접 입력할 필요는 없습니다. 아래 요청문을 그대로 붙여넣으면
Claude Code가 확인하고 처리합니다.

**1. 디버깅** — 먼저 무엇이 어긋났는지 그대로 말하고 고쳐봅니다. 대부분 여기서
해결됩니다.

```text
지금 작업이 책과 다르게 진행됐어.
현재 상태와 화면에 나온 문제를 확인하고 원인을 찾아서 고쳐줘.
```

이 장에서 특히 자주 막히는 자리는 연습용 오류가 의도한 곳보다 넓게 들어간 경우입니다.

```text
연습용 오류가 요약 총 관객수 계산 말고 다른 곳까지 바뀐 것 같아.
보존한 기준 자료와 TOP 20 상세 데이터, 기존 Test가
그대로인지 확인하고 어긋난 곳만 되돌려줘.
```

**2. 내 정상 기록으로 복구** — 해결되지 않으면 실습하면서 내 프로젝트에 남겨둔 정상
기록으로 돌아갑니다. 지금까지 한 작업은 먼저 따로 보존합니다.

```text
현재 작업은 잃지 않도록 먼저 별도로 보존해줘.
이 프로젝트에서 마지막으로 정상 동작했던 상태를 찾아 안전하게 복구해줘.
```

**3. 장별 Source로 재시작** — 그래도 이어갈 수 없을 때 사용합니다. 3장의 남은 실습은
건너뛰게 되므로 마지막 수단입니다.

```text
내 현재 작업을 먼저 안전하게 보존해줘.
아래 3장 완성 Source에서 다시 시작해줘.
https://github.com/buildyourownai-lab/develop-like-a-pro-with-ai/tree/main/chapters/ch03/source/movie-report
준비가 끝나면 3장을 마친 상태인지 확인해줘.
```
