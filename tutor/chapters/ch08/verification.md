# 8장. 누구나 사용할 수 있는 아파트 찾기 서비스를 만듭니다 — 완료 검증 규격

검증은 사용자 요청 범위의 확인입니다. 실제 게시·삭제·결제는 별도 명확한 행동 승인 없이 실행하지 않습니다. 증거를 확보하지 않은 것을 PASS로 입력하지 않습니다.

|목표|확인 기준|근거 종류|기대 결과|
|---|---|---|---|
|ch08-g01|입력과 검색 결과를 기존 기능에 연결|test-run|pass|
|ch08-g02|로딩·0건·입력 오류·외부 오류 구분|human-observation|pass|
|ch08-g03|Secret과 외부 API 호출이 서버에 남음|file-inspection|pass|
|ch08-g04|대상 저장소와 코드 변수명을 Vercel에 대응|human-observation|pass|
|ch08-g05|실제 주소에서 전체 검색 흐름 확인|live-api, live-ui|pass|
|ch08-g06|작은 변경을 검사하고 새 배포를 다시 확인|external-confirmation|pass|

## 다시 확인할 때
코드·실행 환경·대상·인증 설정이 바뀌었으면 관련 근거를 다시 확인합니다. 파일 해시로 감지하지 못하는 외부 정책·권한·키 변화는 사람이 알려야 합니다. 기존 기록을 덮어쓰지 않고 새 기록을 추가합니다.

## 과거 단계와 현재 상태
이 장의 일부 목표는 당시 수행한 과정의 증거입니다. 의도적 FAIL을 고친 뒤에도 당시 FAIL 관찰은 학습 기록으로 남습니다. 같은 대상의 현재 상태는 마지막 정상 검사에서 다시 확인합니다. 원본 증거 파일이 바뀌면 과거 기록도 재확인 대상입니다.
