# 12장. 더 빠르고 비용은 적게 드는 서비스로 개선합니다 — 단계별 힌트

한 요청에는 한 단계만 답합니다. 같은 주제의 “다음 힌트”에서 깊이를 올립니다. 해결 설명은 명시 요청 때만 제시하고 파일 수정은 별도 요청입니다.

## H12-01 · 두 번째가 빠르면 끝인가

**1단계 — 방향:** 속도와 실제 재사용은 다른 증거입니다.

**2단계 — 범위:** 브라우저 캐시인지 서버 저장값인지 구분합니다.

**3단계 — 위치·원인 후보:** 두 번째 요청에서 외부 API·Gemini를 다시 불렀는지 기록을 봅니다.

**정답을 요청했을 때:** 동일 조건 반복·만료·다른 종목을 각각 검사해 재사용과 격리를 확인합니다.

**검증 주의:** 이 설명만으로 원인이 확인됐거나 수정됐다고 말하지 않습니다. 현재 프로젝트의 근거를 먼저 대조합니다.

## H12-02 · 배포 후 DB 연결 실패

**1단계 — 방향:** 로컬과 배포 환경의 변수 이름을 비교합니다.

**2단계 — 범위:** 자동 연결이 만든 Name과 코드가 찾는 Name을 나눕니다.

**3단계 — 위치·원인 후보:** SUPABASE_DATABASE_URL, UPSTASH_REDIS_REST_URL, UPSTASH_REDIS_REST_TOKEN이 로컬과 Vercel에 같은 이름으로 등록되어 있는지 값 노출 없이 확인합니다.

**정답을 요청했을 때:** Vercel에 프로젝트가 사용하는 세 이름으로 연결값을 등록하고 새 배포 후 저장·재조회까지 검증합니다. 무료 플랜을 임의 가정하지 않습니다.

**검증 주의:** 이 설명만으로 원인이 확인됐거나 수정됐다고 말하지 않습니다. 현재 프로젝트의 근거를 먼저 대조합니다.

## H12-MODEL · 모델 지원과 사용량 확인

**1단계:** 공식 지원 여부와 계정 사용량·한도를 확인하는 방법을 안내합니다. 확인하지 못한 계정 상태는 미확인으로 남깁니다.

**2단계:** 모델 교체가 필요하면 사용 가능한 저비용 후보와 비용 조건을 안내합니다.

**3단계:** 힌트 요청만으로 설정을 바꾸거나 유료 전환하지 않습니다. 후보 선택과 실제 변경 요청을 구분합니다.

**해결 방법을 요청했을 때:** 독자가 후보를 선택하고 변경을 요청한 범위에서만 적용합니다. 변경 뒤 실제 응답과 관련 Test를 확인합니다. 11장의 모델 교체 안내로 연결하고, 새 모델을 Cache key로 구분해 옛 브리핑을 재사용하지 않는지 확인합니다.

설명·파일 확인·실제 변경·실행 검증은 각각 구분해 답합니다.
