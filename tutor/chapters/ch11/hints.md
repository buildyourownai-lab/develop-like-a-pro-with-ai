# 11장. 주가부터 공시까지, AI가 한 번에 브리핑합니다 — 단계별 힌트

한 요청에는 한 단계만 답합니다. 같은 주제의 “다음 힌트”에서 깊이를 올립니다. 해결 설명은 명시 요청 때만 제시하고 파일 수정은 별도 요청입니다.

## H11-01 · Vercel 변수명이 헷갈림

**1단계 — 방향:** Name과 Value를 먼저 구분합니다.

**2단계 — 범위:** 서버 코드가 어떤 설정 이름으로 세 키를 읽는지 봅니다.

**3단계 — 위치·원인 후보:** 환경변수 참조 파일·설정 모듈·SDK 전달 위치를 실제 프로젝트에서 확인합니다.

**정답을 요청했을 때:** 키 값은 출력하지 않고 서비스별 변수명·사용 파일·입력 위치를 표로 정리합니다. 같은 Name에 실제 Value를 직접 입력하고 Production 적용 후 새 배포합니다.

**검증 주의:** 이 설명만으로 원인이 확인됐거나 수정됐다고 말하지 않습니다. 현재 프로젝트의 근거를 먼저 대조합니다.

## H11-02 · 문장은 자연스러운데 근거가 없음

**1단계 — 방향:** 문장의 유창함보다 근거 ID를 봅니다.

**2단계 — 범위:** 프로그램 사실·AI 설명·알 수 없는 항목을 나눕니다.

**3단계 — 위치·원인 후보:** 각 설명에 연결된 근거 ID가 입력에 실제 존재하는지 확인합니다.

**정답을 요청했을 때:** 없는 근거 ID나 금지 추정이 있으면 해당 응답을 승인하지 않습니다. 검사를 낮추지 않고 원인을 확인한 뒤 재생성·재검사합니다.

**검증 주의:** 이 설명만으로 원인이 확인됐거나 수정됐다고 말하지 않습니다. 현재 프로젝트의 근거를 먼저 대조합니다.

## H11-03 · 배포 완료인데 브리핑 안 나옴

**1단계 — 방향:** Ready는 배포 상태이지 모든 API 성공이 아닙니다.

**2단계 — 범위:** 실패가 시세·공시·Gemini 중 어디인지 나눕니다.

**3단계 — 위치·원인 후보:** 운영 환경의 변수 이름·모델 지원·응답 코드를 값 노출 없이 확인합니다.

**정답을 요청했을 때:** 실패 원인을 고치고 새 배포에서 실제 브리핑 생성까지 확인합니다. 시험 응답의 PASS를 운영 성공으로 기록하지 않습니다.

**검증 주의:** 이 설명만으로 원인이 확인됐거나 수정됐다고 말하지 않습니다. 현재 프로젝트의 근거를 먼저 대조합니다.

## H11-MODEL-03 · 모델 지원과 사용량 확인

**1단계:** 공식 지원 여부와 계정 사용량·한도를 확인하는 방법을 안내합니다. 확인하지 못한 계정 상태는 미확인으로 남깁니다.

**2단계:** 모델 교체가 필요하면 사용 가능한 저비용 후보와 비용 조건을 안내합니다.

**3단계:** 힌트 요청만으로 설정을 바꾸거나 유료 전환하지 않습니다. 후보 선택과 실제 변경 요청을 구분합니다.

**해결 방법을 요청했을 때:** 독자가 후보를 선택하고 변경을 요청한 범위에서만 적용합니다. 변경 뒤 실제 응답과 관련 Test를 확인합니다.

설명·파일 확인·실제 변경·실행 검증은 각각 구분해 답합니다.
