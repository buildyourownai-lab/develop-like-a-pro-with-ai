# 21장. 내 주식서비스의 챗봇을 기획합니다 — 튜터가 읽는 수업 안내

정본은 `chapter.json`입니다. 독자의 실제 완료 상태는 별도 기록입니다.

## 이번 장에서 완성할 것
docs/ch21-chat-design.md에 기능 범위·답변 구분·사용 흐름·화면 설계·재사용 연결표·22장 구현 순서와 완료 조건을 확정합니다.

## 앞 장에서 이어갈 것
9~12장의 ai-stock-briefing으로 돌아옵니다. 기존 실행 방법과 설정을 재사용하며 14~15장 앱과 기존 작업을 보존합니다. 19~20장 완료는 선행 조건이 아닙니다.

이미 있는 기능: 기존 시장·종목·차트·공시·브리핑과 DB·Cache. 실제 존재하는 공유 API

## 이번 장에서 사용할 것
새 계정·키를 만들거나 챗봇 API를 호출하지 않습니다. 기존 화면 확인에 필요한 실행 방법과 설정만 재사용하고 미확인은 기획서에 남깁니다.

## 진행 순서
이 장의 요청문 P21-01~P21-07은 Code 탭에서 순서대로 사용합니다. 질문 예시는 기획 사례이며 서비스 대화 실습이 아닙니다.

P21-01 시작 → P21-02 기능 범위 → P21-03 답변·사용 흐름 → P21-04 화면 설계 → P21-05 재사용 연결표 → P21-06 구현 계획 → P21-07 완료 확인

제품 기능 추가 없이 docs/ch21-chat-design.md에 기능·사용 흐름·디자인·재사용 연결표·구현 계획을 작성합니다.

## 범위와 완료
최근 확인 종가·기준일만 묻는 질문은 같은 가격 조회 기능으로 처리하며 기간을 되묻지 않습니다. 가격 흐름을 물었는데 기간이 불분명한 경우에만 기간을 확인합니다. 조회 기능은 세 개로 유지합니다.

투자 추천·매매·목표가·미래 가격 예측·공시 본문 수집·자유 웹 검색·RAG·벡터 DB·장기 대화 저장·새 회원/결제 시스템·별도 모바일 앱 수정은 제외합니다. 제품 코드·Test·컴포넌트·작동하는 목업은 만들거나 수정하지 않습니다.

기획서의 필수 목표와 제품 코드·Test 불변을 실제 파일 조사로 확인합니다. 기획 완료에 챗봇 실행·실제 API·촬영을 요구하지 않으며 구현 성공으로 표시하지 않습니다. 이전 실행 목표의 근거는 새 목표에 자동 승계하지 않습니다.

힌트는 한 단계만 제공합니다. 명확한 제작 요청은 현재 장의 범위에서 수행하되, 장 시작·힌트·완료 확인을 구현이나 공개 승인으로 확대하지 않습니다. 책 튜터 자료와 개발 파일을 서비스 Gemini에 전달하지 않습니다.

## 참고 자료의 상태
새 판본의 START·FINISH는 연결 여부를 확인해야 합니다. 과거 실행 기록을 이번 목표의 성공으로 승계하지 않습니다. 설명용 SVG와 설계도는 실제 실행 화면이 아닙니다.

21장은 실행 화면 촬영 슬롯이 없습니다. 실제 챗봇 혼합 답변 확인은 22장에서 합니다.

현재 범위는 로컬 실제 자료 검증까지입니다. 공개 운영 확장 실습·분산 사용량 저장소를 추가하지 않으며 기존 브리핑 Cache는 유지합니다. 범위 축소 후 독자 재현은 아직 실시하지 않았습니다.
