~~~prompt

일반 개념, 가격·기준일, 가격 흐름, 최근 공시와 원문 질문을 대표 사례로 정리해줘.
~~~

## P21-03 · 메인에서 질문부터 시작하게 합니다

~~~prompt
기획서에 답변 구분과 사용 흐름을 추가해줘.
'확인된 자료'는 서버 수치·날짜·공시·출처로 표시하고,
'AI 일반 설명'에는 '최신 확인 자료가 아닙니다'를 붙여줘.
일반 질문에는 빈 사실 카드를 만들지 않고 종목 자료 질문은 관련 항목부터 보여줘.
형식 검사만으로 문장 의미가 모두 정확해진다고 설명하지 마.

메인에서 종목 선택 없이 질문하고, 회사명·코드는 실제 검색 결과로 확인해.
모호하면 실제 후보 최대 5개를 보여주고 선택 전 가격·공시 조회는 하지 않아.
질문은 보관하고 선택 뒤 이어가. 취소·검색 실패 시에도 질문을 잃지 않게 해.
상세의 현재 종목은 최초 기본값이고, 다른 회사를 물으면 대화 대상만 바꿔.
후속 질문은 바뀐 대화 대상을 우선하고, 실제 페이지 이동 때는 새로 시작해.
최근 3회 왕복은 언어 문맥으로만 사용하고 종목 변경 때 이전 근거와 대화를 지워.
전환을 요청한 새 질문은 보관하고 이전 종목의 늦은 응답은 붙이지 않아.
이 흐름과 실패 시 다음 행동을 기획서에 표와 도식으로 정리해줘. 제품 구현은 하지 마.
~~~

## P21-04 · 버튼의 위치와 대화창의 모양을 정합니다

~~~prompt
기존 서비스의 실제 색·글꼴·카드·여백과 하단 조작 위치를 조사하고 화면을 설계해줘.
우하단 플로팅 버튼, 데스크톱 오른쪽 레이어, 모바일 웹 큰 레이어를 계획해.
현재 대상·질문·전송 상태·두 답변 영역·출처·지우기·닫기를 배치해.
관련 자료를 먼저 읽고 추가 자료를 펼치는 순서도 정해줘.
닫기·포커스 복귀·키보드·스크롤·하단 안전 여백의 검사 항목을 적어줘.

메인·상세의 기존 화면을 보존하고 별도 모바일 앱은 바꾸지 마.
기획서에 화면 설계도를 추가하되 실제 실행 화면처럼 표시하지 마.
필요한 화면 상태와 이용자가 다음에 할 행동이 빠졌는지 확인해줘.
제품 컴포넌트나 작동하는 목업은 아직 만들지 마.
~~~

## P21-05 · 기존 기능으로 효율적으로 구현할 방법을 찾습니다

~~~prompt
기획한 세 조회 기능을 실제 코드에 연결할 방법을 조사해줘.
종목 찾기·기간별 가격 요약·공시 목록 조회의 기존 함수 위치·입력·결과·실패·Cache를 표로 적어줘.
최근 공시는 최근 1년 안 최신순 최대 5건과 서버가 만든 DART 원문 링크야.
전체 브리핑 근거·대표 공시·전체 시장 조회를 챗봇에 통째로 재사용하지 마.
기존 검색·가격·공시 하위 함수와 데이터 Cache를 재사용하고,
브리핑 Redis 결과 Cache를 대화 저장소로 전용하지 마.

최근 1년 일봉만 있으면 1개월·3개월을 자르는 작은 Adapter를 계획해.
같은 가격 조회 기능에서 최근 확인 종가·기준일만 묻는 질문도 처리하도록 계획해.
기간별 흐름을 묻는 질문과 구분하고, 종가만 물었을 때 기간 선택을 요구하지 마.
서울 날짜의 달력 월/연, 월말 처리, 요청 기간과 실제 거래일, 등락률 계산 기준을 정해.
1개월·3개월은 고정 거래일 수가 아니라 달력 기간으로 계산해.
자료가 충분한지도 요청한 기간을 기준으로 판단하고 실제 거래일 범위를 보여줘.
연결표 뒤에 AI용 세 함수의 이름과 입력·결과 형식을 확정해줘.
현재 Gemini SDK·모델의 함수 호출 지원은 코드와 공식 문서로 확인해.
미확인·추가 구현·그대로 재사용을 구분해 기획서에 적고 제품 코드는 바꾸지 마.
~~~

## P21-06 · 구현 순서와 완료 조건까지 기획합니다

~~~prompt
기획서를 22장에서 실행할 계획으로 마무리해줘.
대화창·일반 설명 → 종목 찾기·공시 → 답변과 출처 → 가격 기간·후속 대화
→ 제한·실패·회귀·모바일 검수 순서로 구현 단계와 완료 기준을 적어줘.
각 단계의 대표 질문, 화면에서 볼 결과, 실패 시 돌아갈 지점을 연결해줘.

질문은 1,000자, 최근 대화는 3회 왕복으로 제한해.
초기 실행 상한은 모델 3회·조회 4회·전체 30초로 두고,
공시·가격+공시·후보 선택 재개를 제한 안에서 검사한 뒤 확정할 계획을 세워줘.
동일 요청의 동일 조회 재사용, 중복 제출 방지, 자동 재시도 금지를 포함해.
공시 질문의 가격 조회 없음, 일반 질문의 조회 없음, 악성 입력·늦은 응답도 검사해.

실제 API·시험 응답·브라우저 크기 시험·실기기 검증을 구분해.
완료 기준은 실제 자료 검증과 챗봇 활성 상태 확인으로 두고 대화는 기본 켜짐으로 계획해.
CHAT_ENABLED를 설정하지 않아도 활성화하고, 명시적으로 false일 때만 끄게 해.
기획서에 결정·미확인·다음 장에서 검증할 항목을 구분해줘.
완료 선언 전 기능·사용 흐름·디자인·연결표·구현 계획이 서로 맞는지 대조해.
제품 코드와 Test가 바뀌지 않았는지도 확인해줘.
~~~
