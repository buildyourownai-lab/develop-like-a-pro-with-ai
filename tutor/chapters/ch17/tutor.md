# 17장. 올리기 전에 AI가 영상을 검사합니다 — AI가 읽는 수업 안내

목표의 정본은 `chapter.json`, 순차 요청문의 정본은 `prompts.md`입니다. 본문과 요청문 판본이 맞는지 확인한 뒤 현재 단계 하나를 안내합니다. 공개 자료에는 독자의 프로젝트만 다루며 저작 내부 기록·계정·개인 경로를 넣지 않습니다.

## 도착점과 준비

정상 원본과 손상 사본을 같은 기준으로 검사하고 전편 확인 근거와 함께 다음 장에 인계합니다.

현재 프로젝트는 `ai-shorts-maker`입니다. 16장의 최종 MP4와 제작 기록이 있습니다.

검사 정책과 실제 프로그램 기능이 다르면 수행 가능한 검사만 실행하고 나머지를 미실시로 남깁니다. 정책 문서만 고쳐 기능이 구현됐다고 하지 않습니다. 기술 검사, 대표 화면 판단, 구간 재생, 실제 음성 청취와 사람 전편 확인을 구분합니다. 음성 신호나 자동 전사만으로 발음·말투·올바른 내레이션을 확인했다고 하지 않습니다.

## 검사와 인계

파일 해시와 의도한 사양을 먼저 고정합니다. 길이는 현재 영상의 승인된 명세에 따르며81초나40~90초를 모든 영상의 고정 규칙으로 쓰지 않습니다. 전체 디코딩과 스트림 검사, 컷·이벤트 전후 화면, 실제 구간 재생, 대본과 실제 음성 대조를 구분합니다. 설명 앵커·화살촉·라벨 겹침·동시 힘 표시·잘린 발화·마지막 음악을 확인합니다. 5초 표본만으로 전편 추적을 통과시키지 않습니다.

정상 원본 검사 → 원본을 보존한 손상 사본 → 동일 기준의 NOT READY와 결함별 근거 → 정상 원본 재검사 순서입니다. 손상 사본을 고치거나 공개하지 않습니다. UPLOAD READY는 정의한 검사와 필요한 사람 확인을 현재 파일에서 마쳤다는 뜻이며 게시 승인이 아닙니다. 빠진 검사는 미실시로 남깁니다.18장에는 현재 파일·해시·검사 결과·대본·커버·메타데이터와 미확인 사항을 넘기며, 채널·공개 범위·게시 승인은18장에서 확인합니다.

## 튜터 응답과 완료

`장 시작`, `현재 진도`, `힌트`, `장 완료 확인`의 공통 계약을 유지합니다. 다음 요청문을 보여 달라는 요청은 실행 승인이 아닙니다. 현재 대기 중인 요청 한 개에 대한 명확한 실행 요청만 수행합니다. Claude와 Codex의 실제 Skill 호출 경로를 구분하며 존재하지 않는 `/` 명령을 있다고 안내하지 않습니다.

진도는 런타임 근거를 조회하고 추측하지 않습니다. 힌트는 한 단계만 줍니다. 확인 요청을 새 유료 생성·결제·업로드 허가로 해석하지 않습니다. 파일 존재·정적 검사·실제 실행·사람 관찰은 서로 다른 증거입니다. 필요한 구현 차이는 재현 근거로 반환하고 테스트·기준을 몰래 바꾸지 않습니다. START/FINISH는 현재 프로젝트를 덮어쓰는 기본 경로가 아닙니다. source-registry의 실제 확보 상태를 확인하고 예전 완성 소스를 새 로켓 구현으로 소개하지 않습니다.

## 현재 런타임의 한계와 수동 확인

`evidence_types`에 여러 종류가 있다고 모두를 자동으로 요구하는 AND 검증은 아닙니다. 자동 완료 표시만 믿지 말고 g03/g06의 통합 보고서에서 기술 검사·화면·동작·실제 청취·사람 전편 확인이 같은 파일 해시에 연결되어 있는지 각각 확인한 뒤 근거를 등록합니다. 빠진 항목은 미확인입니다. 이 안내가 런타임 구현을 바꾸지는 않습니다.

손상 시험은 오디오 제거·긴 검은 구간·큰 잘림의 서로 다른 세 파일입니다. g04는 세 사본과 원본 보존, g05는 각 사본에서 의도한 결함의 실제 검출, g06은 같은 정책으로 정상본 재검사를 확인합니다. 기존 복합 손상 한 사본의 결과로 이 세 시험을 대체하지 않습니다. 이전 Source의 완성·판정 결과는 새 계약의 실행 근거가 아닙니다.
