## P17-02 · 1. 검사할 파일과 기준을 먼저 고정합니다

~~~prompt
16장에서 확정한 <최종 MP4 경로>를 이번 장의 검사 원본으로 지정할게.
현재 ai-shorts-maker 프로젝트와 파일을 실제로 확인해줘.

원본은 덮어쓰지 말고 파일명, SHA-256, 실제 길이·해상도·프레임률,
영상/오디오 스트림을 기록해. 이 파일에 맞는 대본과 컷표도 찾아 대조해.
없거나 다른 판본이면 추측해서 채우지 말고 필요한 자료를 알려줘.

검사 정책 초안을 prototypes/youtube-shorts/chapter-17/review-policy.json에
정리해줘. 의도한 언어, 최종 길이와 허용 오차, 해상도, 말이 있는 구간과
말이 없는 구간, 검은 화면·오디오·화면·움직임의 기준을 구분해.
정책·검사 기록 파일은 작성하되 정책을 보여준 뒤 내 확인을 기다려.
원본 미디어 수정·재생성·업로드는 하지 마.
~~~

## P17-03 · 2. 검사 Skill을 만듭니다

~~~prompt
방금 확인한 정책으로 업로드 전 검사 Skill을 만들어줘.
이름은 `video-upload-review`로 해. 기존 Skill이 있으면 차이부터 보여줘.

실제 수행할 절차는 다음과 같아.
1. 입력 파일의 해시와 정책 판본을 기록하고 전체 디코딩·길이·해상도·
   스트림·오디오 신호·검은 화면 후보를 검사한다.
2. 컷별 시작/중간/끝과 설명 등장·퇴장, 빠른 동작 전후 화면을 뽑는다.
   표본 프레임과 필요한 재생 구간을 구별한다.
3. 화면·움직임·사실·대본·실제 음성의 결과를 각각 기록한다.
   직접 보거나 듣지 못하면 미확인으로 남긴다.
4. 사람의 전체 재생 확인을 같은 파일 해시와 연결한다.

필수 항목이 실패하거나 미확인이면 NOT READY로 보고하고,
모든 필수 근거가 있을 때만 UPLOAD READY로 판정해.
기술 검사만 끝났으면 '기술 검사 완료, 나머지 미확인'이라고 구분해.
자동 수정·유료 생성·업로드는 하지 마.

현재 작업 도구가 읽는 프로젝트 Skill 위치에 저장하고 실제 발견되는지
확인해. Claude Code라면 .claude/skills/video-upload-review/SKILL.md와
명령 목록을 확인해. Skill 파일 존재와 실행 성공은 따로 보고해.
~~~

## P17-04 · 3. 파일 상태와 화면·움직임을 검사합니다

~~~prompt
video-upload-review로 고정한 최종 원본을 검사해줘.
확정한 review-policy.json을 그대로 사용하고 원본 해시를 다시 대조해.

프로그램으로 전체 파일을 읽고 결과와 실행 오류를 기록해.
이어 컷별 대표 화면, 설명 등장·퇴장과 빠른 동작 전후 화면을 확인해.
추적이나 컷 연결은 실제 짧은 재생 구간으로 확인하고,
정지화면만 볼 수 있으면 그 한계를 남겨.

문제는 시간, 대상, 근거, 영향, 수정할 층을 적어 보여줘.
영상·자막·음성·믹스 중 무엇이 문제인지 나누고 아직 수정하지 마.
사람의 전체 재생과 실제 청취가 남았다면 최종 준비 완료로 판정하지 마.
~~~

## P17-05 · 4. 대본과 실제 음성을 맞춰 봅니다

~~~prompt
확정 대본과 현재 MP4의 실제 내레이션을 문장별로 대조해줘.
말이 들어 있는 구간마다 시작/끝, 의도한 문장, 실제 들리는 말,
존댓말·발음·숫자·잘림·다른 음성과의 겹침을 기록해.

로켓의 '올라갈수록 공기는 희박해집니다'를 포함해 모든 종결 표현을 확인해.
전사 결과는 단서를 찾는 데 쓰되 직접 듣지 못한 항목은 청취 통과로 적지 마.
원래 효과음과 은은한 배경음은 살리고, 설명을 가리는 구간만 지적해.
엔딩의 마지막 말과 소리가 끝까지 들리는지도 확인해.

내가 같은 파일을 처음부터 끝까지 소리와 함께 볼 수 있도록 열어주거나
실제 파일 위치를 알려줘. 내가 확인하기 전에는 전체 재생 완료로 기록하지 마.
~~~

## P17-06 · 5. 더 좋은 장면으로 고칠지 판단합니다

~~~prompt
지금까지 찾은 문제와 내 전체 재생 의견을 합쳐 수정 목록을 만들어줘.
내가 아직 전체 재생 결과를 말하지 않았다면 먼저 기다려.

수정 필수/개선 권장/취향으로 나누고, 시간과 고칠 층을 적어.
영상미는 첫 화면의 호기심, 서로 다른 공간과 시점, 카메라·대상의 목적 있는
움직임, 조명과 색, 설명 가독성, 마지막 여운으로 검토해.
참고 영상이 있으면 같은 역할의 장면과 비교하되 제작 도구를 추측해 단정하지 마.

트림·설명 위치·음성·믹스로 해결할 수 있는지 먼저 판단하고,
재생성이 필요하면 이유와 범위를 제시해. 내가 선택한 수정만 적용해.
수정본은 별도 파일로 만들고 영향받은 항목을 다시 검사해.
내가 수정본 전체를 다시 재생한 뒤 결과를 확인해줘.
~~~

## P17-07 · 6. 손상 사본으로 검사기를 시험합니다

~~~prompt
현재 확인한 정상본은 보존하고, 별도 시험 폴더에 손상 사본 세 개를 만들어줘.
1. 오디오 스트림을 제거한 사본
2. 의도하지 않은 긴 검은 구간을 넣은 사본
3. 설명과 중심 대상이 잘리도록 크게 잘라 원래 출력 크기로 맞춘 사본

각 사본은 원본과 다른 파일명·해시로 기록하고 다른 결함을 섞지 마.
검은 구간은 정책의 탐지 기준보다 충분히 길게 넣고 위치를 기록해.
잘림은 원본과 비교할 수 있도록 구간과 의도한 결함을 기록해.

정상본에 적용한 동일 정책·동일 검사 절차로 세 사본을 각각 검사해.
각각 NOT READY가 나와야 하며, 의도한 결함의 검출 근거를 확인해.
파일명이나 정답 목록만 보고 실패 처리하지 말고 실제 파일을 검사해.
못 잡거나 확인하지 못한 결함은 검사기의 미완료로 남겨.
정상본을 수정하거나 어느 사본도 업로드하지 마.
~~~

## P17-08 · 7. 정상 원본을 다시 검사하고 다음 장으로 넘깁니다

~~~prompt
손상 사본 시험 뒤 보존한 정상 원본을 다시 검사해줘.
손상 시험에 들어가기 직전 고정한 정상본 해시와 같은지 대조하고,
손상 시험과 동일한 최종 정책을 써.
검사기를 고쳤다면 정상본과 세 손상 사본을 모두 다시 검사해.

정상→손상 사본별 거부→정상 재검사의 대상·정책 판본·근거를 묶어줘.
프로그램, 화면, 동작, 내용, 실제 청취, 사람 전체 재생을 따로 표시해.
실패나 미확인이 남으면 NOT READY와 다음 행동을 알려줘.
필수 근거를 모두 확인한 같은 파일만 UPLOAD READY로 표시해.

최종 MP4·해시·대본·컷표·정책·검사 기록과 사람의 확인 범위를
18장에 넘길 목록으로 정리해. 손상 사본은 시험용으로 분리해.
어느 파일도 업로드하거나 공개하지 마.
~~~
