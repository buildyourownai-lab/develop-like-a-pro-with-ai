# 20장. 허용한 댓글에만 자동으로 답하게 합니다 — 튜터가 읽는 수업 안내

> 정본: `chapter.json`. 이 파일은 그 정본에서 생성했습니다. 독자의 실제 완료 상태는 별도 기록입니다.

## 이번 수업의 도착점
승인한 영상·종류·시간 범위에서 자동답글을 보내고, 중복·결과 미확인·중지를 실제로 확인합니다.

## 시작 상태와 프로젝트
`ai-media-works` — 19장의 로컬 조회·분류·초안·두 검사가 준비돼 있고 댓글 사용이 가능한 내 영상 한 편이 있습니다.

이미 만든 것: 19장의 댓글 조회·분류·초안·검사. 기존 OAuth 앱·Gemini 계정. Vercel·Supabase 경험  
이번에 더할 것: 제한된 답글 전송, 시작 시각·기록·동시 실행 잠금, 예약·중지·재개

## 시작 전에 안내할 준비
서비스: youtube, google-cloud, gemini, supabase, vercel. 해당 `services/`의 공식 입구·계정·권한·비용·실제 확인 방법을 안내합니다. 필요한 절에서 준비하며 계정을 한꺼번에 새로 만들지 않습니다. 인증정보가 다른 폴더에도 저절로 존재한다고 가정하지 않습니다.

도구: Node.js, 기존 Next.js 서버, DB의 원자적 상태 관리, Supabase Cron·Vault. 설치와 실제 실행 가능 상태를 구분합니다.

## 범위와 진행 방식
Google Chat·원격 Worker·경영 보고·영상 자동 제작·소개 댓글·댓글 삭제·차단·전체 채널 운영·공개 관리 UI를 추가하지 않습니다.

개발 요청은 명시한 범위로 구현합니다. 힌트만 요청하면 `hints.md`에서 현재 증상에 맞는 한 단계만 제공합니다. “정답”은 설명이며 수정 승인으로 바꾸지 않습니다. 아직 시도하지 않았더라도 용어와 준비 설명을 요청할 수 있습니다.

“이번 장 시작해”는 명세·폴더·준비·첫 행동을 확인하는 요청입니다. 코드를 만들거나 초기화하지 않습니다. “현재 진도 알려줘”는 실제 근거를 바탕으로 완료·미확인·실패·재확인 상태를 읽습니다. “지금 뭐 하면 돼?”에는 선행 조건이 충족된 첫 작업 하나만 알려줍니다. “장 완료 확인해줘”는 정의된 검사와 근거를 대조하며, 통과를 위해 코드·기준을 고치거나 외부 게시·결제를 하지 않습니다.

## 참고 소스와 증거
START·FINISH는 선택한 재개·비교의 기준점입니다. 순서대로 따라온 독자의 프로젝트는 계속 사용합니다. 현재 판본 Source가 실제 결합되지 않았다면 미연결이라고 안내하고 옛 원격 챗봇 소스로 대체하지 않습니다. 현재 제공 Source의 검사 범위는 장별 verification에서 확인합니다. 로컬 검사와 독자의 실계정 수행은 별도 증거입니다.

구현·검사 보고서를 모두 마무리한 뒤 현재 상태 목표를 등록합니다. 추가 보고 파일 생성만으로도 프로젝트 지문이 바뀔 수 있으므로, 변경 후 재확인할 목표를 그대로 남깁니다. 과정 관찰의 과거 증거와 지금의 기능 상태를 혼동하지 않습니다.

대상 준비 → 새 시험 댓글 → 재조회 → 문장 확인·수동 승인 → 예약 대상·처리 조건 확인 순서입니다. 일반 중지는 예약만 끄고 새 수동 승인은 별도입니다. 결과 미확인 중단은 두 전송을 모두 막습니다.

운영 상태를 확인할 때: 일반 중지는 예약 전송만 끄며 새 수동 승인은 별도입니다. 결과 미확인 중단은 두 전송을 모두 막고 enable로 해제하지 않습니다. 30일이 지난 기록은 다음 예약 호출 때 삭제하며, 예약 호출을 없애면 남은 기록도 직접 정리합니다. 사람 확인 건수는 19장 화면에서 댓글을 재조회해 종류·이유를 확인합니다. 최신 20개보다 이전 댓글은 해당 영상의 YouTube 댓글 화면에서 직접 찾습니다.
