# 2장 검증에 사용한 파일

저자가 2장을 확인할 때 실제로 돌린 결과입니다. 실습에 필요한 파일은 아니고, 저자가
어떻게 확인했는지 그대로 보여주기 위한 자료입니다.

| 파일 | 무엇인가 |
|---|---|
| [check-result.json](check-result.json) | 2회 실행의 검사 결과와 측정 조건 |

2장이 만드는 기준 자료와 자동 검사는 실습 결과물이므로 장별 Source에 있습니다.

[chapters/ch02/source/movie-report/](../../../chapters/ch02/source/movie-report/)

## 검사 항목 개수가 실행마다 다릅니다

2회 실행에서 8개와 7개가 나왔습니다. 요청한 완료 조건 일곱 가지는 같은데 Claude가 그것을
몇 개의 항목으로 나누는지가 달라집니다.

| 실행 | 검사 항목 | 결과 |
|---|---|---|
| 1 | 8개 | 전항목 통과 |
| 2 | 7개 | 전항목 통과 |

두 실행 모두 TOP 20 전체의 영화명·관객수·매출액이 기준 자료와 전건 일치했고, 그 기준
자료는 KOBIS 공식통계와 20/20 일치했습니다. 개수가 아니라 이것이 판정 기준입니다.

## 검사가 다른 사람의 보고서에서는 돌아가지 않습니다

이것은 결함이 아니라 이 장의 구조입니다. 보고서는 실행마다 시트 이름과 표 위치가
달라지므로, 2장의 검사도 각자의 보고서에 맞춰 만들어집니다. 검사가 보고서와 같은 폴더에
사는 이유입니다.

두 실행이 만든 기준 자료도 시트 이름이 서로 달랐습니다. **어긋난 것은 구조뿐이고 숫자가
다른 경우는 한 건도 없었습니다.**

## 돌려보기

```bash
# 2장 Source를 받아 그대로
python3 build_movie_report.py
python3 -m pytest tests/ -v

# 1장 확인 목록 7개가 여전히 통과하는지 (시트 이름과 열 번호를 모르는 검사)
python3 ../../chapter-01/artifacts/check7.py <경로>/movie-report-2024.xlsx
```

두 실행의 보고서 모두 1장 확인 목록 7개를 그대로 통과했습니다. 2장 작업이 1장 결과를
깨뜨리지 않았다는 뜻입니다.
