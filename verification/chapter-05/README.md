# 5장 검증 — 돌아갈 곳을 만들고, 정말 돌아가는지 확인합니다

> **4장 도착점에서 2회 실행 · 2회 모두 검사 8개 통과를 확인한 뒤 정상 기준을 기록**
> 보고서만 되돌리고 새 메모는 보존 2/2 · 복구 뒤 검사 8개 재통과 2/2 · 최종 확인 2026-08-29

## 실제로 만들어봤습니다

책에 인쇄된 요청문만으로 정상 상태를 기록하고, 필요한 파일만 되돌릴 수 있는지
확인했습니다.

- 요청문은 책 5장에 나오는 문장을 **글자까지 그대로** 썼습니다.
- **빈 폴더에 4장을 끝낸 상태를 놓고 검사 8개 통과를 먼저 확인한 뒤** 같은 세션에서
  5장 요청문을 순서대로 이어 붙였습니다.
- **책에 없는 추가 지시를 보태지 않았습니다.**
- 서로 독립된 빈 폴더에서 **2회** 돌렸고, 두 번 모두 공통 작업 원칙이 4장까지의 내용만
  있는 상태에서 시작했습니다.

5장의 완료 기준은 여섯 가지입니다. **두 실행 모두 여섯 가지 전부 통과했습니다.**

| | 확인 항목 | 실행 2회 |
|---:|---|---|
| 1 | 기록하기 전에 Test 전체를 실행하고 통과를 확인한다 | 통과 |
| 2 | 기록하면 안 되는 정보와 임시 파일을 골라내고 무엇을 제외했는지 설명한다 | 통과 |
| 3 | 기록한 기준과 지금 상태를 비교해 바뀐 기존 파일과 새로 생긴 파일을 구분한다 | 통과 |
| 4 | 되돌리기 전에 무엇이 되돌아가고 무엇이 남는지 먼저 설명한다 | 통과 |
| 5 | 보고서만 기준 상태로 돌아가고 새 메모는 그대로 남는다 | 통과 |
| 6 | 공통 CLAUDE.md에 새 원칙 두 개가 기존 내용을 지우거나 중복하지 않고 더해진다 | 통과 |

두 실행 모두 Plan mode에서 큰 변경을 요청해 **영향받는 파일과 작업 순서, 확인할 Test,
위험 요소가 담긴 계획을 받고, 프로젝트 파일이 하나도 바뀌지 않은 것**을 파일 검사로
확인했습니다.

5장은 movie-report의 마지막 장입니다. 이 장을 끝내면 프로젝트에 돌아갈 기준과 컴퓨터
밖 보관 자리, 두 가지 새 공통 원칙이 더해집니다.

| 무엇 | 어디 |
|---|---|
| PART 1(1~5장)을 끝낸 완성 프로젝트 | [chapters/ch05/source/movie-report/](../../chapters/ch05/source/movie-report/) |
| 완성된 프로젝트 저장소 | [movie-report](https://github.com/buildyourownai-lab/movie-report) |

장별 Source를 빈 폴더에 단독으로 놓고 실행해 보고서가 만들어지고 검사 8개가 모두
통과하는 것까지 확인했습니다. 첫 시트의 제목은 `2024년 영화 흥행 TOP 20`입니다.

프로젝트 저장소에는 5장에서 만든 정상 기록이 실제로 올라가 있고, 저장소는 비공개
상태입니다.

## 자동 검사도 해봤습니다

5장은 검사를 새로 만들지 않습니다. 4장까지 만든 검사를 그대로 사용합니다.

| | 개수 |
|---|---:|
| 5장 Source에서 돌린 검사 전체 | 8개 |
| 이 장에서 새로 생긴 검사 | 0개 |

돌린 검사 코드는 5장 Source 안에 있습니다.

| 파일 | 무엇을 확인하는가 | 검사 |
|---|---|---:|
| [tests/test_movie_report.py](../../chapters/ch05/source/movie-report/tests/test_movie_report.py) | TOP 20 구조, 기준 자료와 영화명·관객수·매출액 일치, 출처와 조회 기준 연도, 요약 관객수 합계 | 8개 |
| [tests/conftest.py](../../chapters/ch05/source/movie-report/tests/conftest.py) | 보고서와 기준 자료를 열어 검사에 넘겨주는 준비 코드 | 0개 |

이 장에서 확인한 것은 검사 개수가 아니라 **검사를 언제 실행하는지**입니다.

| 실행 | 기록 전 검사 | 기록 | 되돌린 것 | 남긴 것 | 복구 뒤 검사 |
|---|---|---|---|---|---|
| 1 | 8/8 통과 | 정상 기준 기록 | 보고서의 행 높이 변경 | notes/next-ideas.md | 8/8 통과 |
| 2 | 8/8 통과 | 정상 기준 기록 | 보고서의 행 높이 변경 | notes/next-ideas.md | 8/8 통과 |

두 실행 모두 임시 파일을 기록에서 제외하고 무엇을 넣고 무엇을 뺐는지 설명했습니다.
되돌리기 요청에서는 실행 전에 무엇이 사라지고 무엇이 남는지 먼저 알려준 뒤 보고서만
기준 상태로 돌렸습니다. 단계별 결과는
[artifacts/check-result.json](artifacts/check-result.json)에 있습니다.

## 직접 확인해볼 수 있습니다

책의 5장을 그대로 따라 하시면 됩니다. 요청문은
[chapters/ch05/prompts.md](../../chapters/ch05/prompts.md)에 책에 나오는 순서대로
있습니다.

기록한 기준과 지금 상태가 어떻게 다른지 직접 보고 싶으면 Claude에게 물어보면 됩니다.

```text
지금까지 기록한 정상 기준과 현재 상태를 비교해서
어떤 파일이 바뀌었고 어떤 파일이 새로 생겼는지 알려줘.
아직 아무것도 되돌리지 말아줘.
```

## 이런 한계가 있습니다

- **Git 기록의 개수와 각 기록의 설명은 실행마다 다릅니다.** 기준은 기록의 모양이 아니라,
  검사를 통과한 상태만 기준으로 남았는지입니다.
- **Excel 파일은 줄 단위로 무엇이 바뀌었는지 읽기 어렵습니다.** 어떤 파일이 바뀌었는지는
  Claude의 설명으로 확인하고, 숫자와 구조가 맞는지는 검사로 확인하시면 됩니다.
- **Checkpointing과 Plan mode의 화면 위치와 메뉴 이름은 Claude Code 버전에 따라 달라질 수
  있습니다.** 되돌릴 지점을 고르는 목록과 계획만 보여주는 모드가 있다는 것만 확인하면
  됩니다.
- **Git으로 돌아갈 수 있는 것은 Git에 기록해둔 상태뿐입니다.** 아직 기록하지 않은 변경이나
  프로젝트 밖에서 일어난 일까지 되돌려주지는 않습니다.
