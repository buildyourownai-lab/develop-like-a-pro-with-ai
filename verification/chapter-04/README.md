# 4장 검증 — 규칙을 남기면 다음 작업이 실제로 달라집니다

> **빈 폴더에서 2회 실행 · 2회 모두 공통 원칙과 프로젝트 규칙이 중복 없이 분리**
> 제목 변경만 요청해도 기존 검사 8개를 스스로 실행 2/2 · 전부 통과 확인 뒤 완료 보고 2/2 · 최종 확인 2026-08-29

## 실제로 만들어봤습니다

책에 인쇄된 요청문만으로 지속 규칙이 실제로 다음 작업에 쓰이는지 확인했습니다.

- 요청문은 책 4장에 나오는 문장을 **글자까지 그대로** 썼습니다.
- **빈 폴더에 3장을 끝낸 상태를 놓고 검사 8개 통과를 먼저 확인한 뒤** 같은 세션에서 4장
  요청문 3개를 이어 붙였습니다.
- **책에 없는 추가 지시를 보태지 않았습니다.**
- 서로 독립된 빈 폴더에서 **2회** 돌렸고, 두 번 모두 공통 작업 원칙이 **없는 상태**에서
  시작했습니다.

4장의 완료 기준은 여섯 가지입니다. **두 실행 모두 여섯 가지 전부 통과했습니다.**

| | 확인 항목 | 실행 2회 |
|---:|---|---|
| 1 | 공통 CLAUDE.md와 프로젝트 CLAUDE.md가 중복 없이 나뉜다 | 통과 |
| 2 | 공통 쪽에 영화 보고서 전용 규칙이 섞이지 않는다 | 통과 |
| 3 | 자세한 문제 확인 절차가 요청한 다섯 단계 순서로 채워진다 | 통과 |
| 4 | 프로젝트 CLAUDE.md가 한 번 있었던 사건을 규칙으로 남기지 않는다 | 통과 |
| 5 | 제목 변경만 요청해도 기존 검사 전체를 스스로 실행하고 전부 통과한다 | 통과 |
| 6 | 전부 통과를 확인한 뒤에만 완료를 보고한다 | 통과 |

## 완성된 결과를 공개합니다

4장이 실제로 만드는 것은 지속 규칙 세 파일입니다.

| 파일 | 무엇인가 |
|---|---|
| ~/.claude/CLAUDE.md | 모든 프로젝트에서 참고할 공통 작업 원칙(프로젝트 밖 파일) |
| movie-report/CLAUDE.md | 영화 보고서 프로젝트에서만 참고할 규칙 |
| movie-report/docs/debug-procedure.md | 문제가 생겼을 때 따르는 자세한 확인 절차 |

공통 파일은 특정 프로젝트에 속하지 않으므로 장별 Source에 넣지 않았습니다. 나머지 둘을
포함한 4장 도착점 전체는
[chapters/ch04/source/movie-report/](../../chapters/ch04/source/movie-report/)에 있습니다.
이 폴더를 빈 폴더에 단독으로 놓고 실행해 보고서가 만들어지고 검사 8개가 모두 통과하는
것까지 확인했습니다.

## 자동 검사도 해봤습니다

4장은 검사를 새로 만들지 않습니다. 3장까지 만든 검사를 그대로 사용합니다.

| | 개수 |
|---|---:|
| 4장 Source에서 돌린 검사 전체 | 8개 |
| 이 장에서 새로 생긴 검사 | 0개 |

돌린 검사 코드는 4장 Source 안에 있습니다.

| 파일 | 무엇을 확인하는가 | 검사 |
|---|---|---:|
| [tests/test_movie_report.py](../../chapters/ch04/source/movie-report/tests/test_movie_report.py) | TOP 20 구조, 기준 자료와 영화명·관객수·매출액 일치, 출처와 조회 기준 연도, 요약 관객수 합계 | 8개 |
| [tests/conftest.py](../../chapters/ch04/source/movie-report/tests/conftest.py) | 보고서와 기준 자료를 열어 검사에 넘겨주는 준비 코드 | 0개 |

이 장에서 확인한 것은 검사 개수가 아니라 **누가 검사를 실행했는지**입니다.

| 실행 | 기존 검사 | 요청하지 않은 검사 실행 | 결과 | 완료 보고 |
|---|---:|---|---|---|
| 1 | 8개 | 실행함 | 8/8 통과 | 통과 확인 뒤 |
| 2 | 8개 | 실행함 | 8/8 통과 | 통과 확인 뒤 |

세 번째 요청문에는 검사를 실행하라는 말도, 통과를 확인한 뒤 완료하라는 말도 없습니다.
두 실행 모두 Claude가 공통 작업 원칙을 참고해 스스로 검사 8개를 실행하고, 전부 통과를
확인한 뒤에 완료를 보고했습니다.

두 실행 모두 프로젝트 CLAUDE.md에 공통 원칙을 중복해서 넣지 않았고, 3장에서 있었던 특정
사건도 규칙으로 남기지 않았습니다. 단계별 결과는
[artifacts/check-result.json](artifacts/check-result.json)에 있습니다.

## 직접 확인해볼 수 있습니다

책의 4장을 그대로 따라 하시면 됩니다. 요청문은
[chapters/ch04/prompts.md](../../chapters/ch04/prompts.md)에 책에 나오는 순서대로
있습니다. **세 개를 순서대로 모두 사용하세요.**

공통 CLAUDE.md와 프로젝트 CLAUDE.md가 실제로 중복 없이 나뉘었는지 직접 확인하고 싶으면
Claude에게 물어보면 됩니다.

```text
~/.claude/CLAUDE.md와 movie-report/CLAUDE.md를 열어서 보여줘.
같은 내용이 두 곳에 중복돼 있는지, 한 번 있었던 오류가
규칙으로 남아 있는지 확인해줘.
```

## 이런 한계가 있습니다

- **세 파일의 문장은 실행마다 다릅니다.** 소제목과 표현이 이 저장소와 달라도 정상입니다.
  기준은 문장이 같은지가 아니라 공통 원칙과 프로젝트 규칙이 중복 없이 나뉘었는지입니다.
- **제목을 바꾼 시트도 실행마다 다를 수 있습니다.** 원고가 「보고서 첫 화면」이라고만
  가리키므로, 여러분의 결과에서는 다른 시트의 제목이 바뀔 수 있습니다.
- **CLAUDE.md에 적힌 규칙이 시스템적으로 강제되는 것은 아닙니다.** 두 실행 모두 검사가
  스스로 실행됐지만, 그것은 Claude가 참고하는 지침이기 때문입니다.
- **공통 ~/.claude/CLAUDE.md는 여러분의 컴퓨터 전체에 적용됩니다.** 이 장 이후에 만드는
  모든 프로젝트에서 Claude가 참고하므로, 내용을 확인한 뒤 진행하시길 권합니다.
