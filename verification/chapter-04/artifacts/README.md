# 4장 검증에 사용한 파일

저자가 4장을 확인할 때 실제로 돌린 결과입니다. 실습에 필요한 파일은 아니고, 저자가
어떻게 확인했는지 그대로 보여주기 위한 자료입니다.

| 파일 | 무엇인가 |
|---|---|
| [check-result.json](check-result.json) | 2회 실행의 단계별 결과와 측정 조건 |

4장이 사용하는 검사와 코드, 그리고 이 장에서 생긴 두 규칙 파일은 장별 Source에 있습니다.

[chapters/ch04/source/movie-report/](../../../chapters/ch04/source/movie-report/)

## 두 실행이 같았던 것

두 실행 모두 공통 작업 원칙이 없는 상태에서 시작했고, 세 파일이 아래처럼 나뉘어
생겼습니다.

| 파일 | 들어간 것 | 들어가지 않은 것 |
|---|---|---|
| ~/.claude/CLAUDE.md | 완료 전 검사 실행, 실패 시 완료 선언 금지, 문제 발생 시 재현 → 증거로 원인 좁히기 → 최소 수정 → 재실행 | KOBIS 같은 영화 보고서 전용 규칙 |
| movie-report/CLAUDE.md | KOBIS 기준 확인, 출처와 조회 기준 연도 남기기, 확인할 수 없는 흥행 원인 추측 금지 | 공통 작업 원칙, 3장에서 있었던 20위 사건 |
| movie-report/docs/debug-procedure.md | 요청문이 지정한 다섯 단계를 그 순서대로 | -- |

절차 문서의 다섯 단계는 두 실행이 같은 순서였습니다. 고치지 않은 채로 같은 실패를 다시
확인하고, 보존한 기준 자료부터 값을 차례로 비교해 처음 달라지는 지점을 찾고, 확인된
사실과 아직 추측인 것을 나눠 적고, 증거로 원인을 확인한 뒤 필요한 부분만 고치고, 실패했던
검사와 기존 검사 전체를 다시 실행하는 순서입니다. 두 실행 모두 그 안에서 이 프로젝트의
기준 자료 파일 이름을 직접 가리켰습니다.

## 제목만 바꿔달라고 한 뒤

| 실행 | 기존 검사 | 요청하지 않은 검사 실행 | 결과 | 완료 보고 |
|---|---:|---|---|---|
| 1 | 8개 | 실행함 | 8/8 통과 | 통과 확인 뒤 |
| 2 | 8개 | 실행함 | 8/8 통과 | 통과 확인 뒤 |

두 실행 모두 첫 화면인 TOP20 시트의 제목을 바꿨습니다. **원고가 「보고서 첫 화면」이라고
가리키므로 여러분의 결과에서는 다른 시트의 제목이 바뀔 수도 있습니다.** 확인할 것은 어느
시트가 바뀌었는지가 아니라, 검사를 실행하라는 말을 하지 않았는데도 기존 검사 전체가
실행되고 전부 통과한 뒤에 완료 보고가 나왔는지입니다.

## 문장은 실행마다 다릅니다

세 파일의 소제목과 문장은 두 실행이 서로 달랐습니다. 나뉘는 방식만 같았습니다. 여러분의
결과에서 문장이 또 달라도 정상입니다.

## 돌려보기

공통 CLAUDE.md와 프로젝트 CLAUDE.md가 실제로 중복 없이 나뉘었는지 확인하려면 Claude에게
물어보면 됩니다.

```text
~/.claude/CLAUDE.md와 movie-report/CLAUDE.md를 열어서 보여줘.
같은 내용이 두 곳에 중복돼 있는지, 한 번 있었던 오류가
규칙으로 남아 있는지 확인해줘.
```
