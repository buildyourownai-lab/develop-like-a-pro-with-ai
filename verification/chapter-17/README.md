# 17장 검증 — 정상 영상은 통과하고 망가뜨린 영상은 실패했습니다

> **같은 기준으로 두 영상을 검사해 정상은 UPLOAD READY, 손상본은 NOT READY가 나왔습니다**
> 검사 13항목 · 손상본에서 5항목 실패 · 최종 확인 2026-09-06

## 실제로 만들어봤습니다

책 17장의 요청문만으로 업로드 전 검사 기준을 정하고, 16장에서 만든 영상과 일부러
망가뜨린 사본을 **같은 기준으로** 검사했습니다. 손상본이라고 기준을 더 엄하게 하거나
예상 결과를 미리 알려주지 않았습니다.

- 검사 기준은 책에 나오는 문장으로 정하고 review-policy.json 한 곳에 모았습니다.
- 정상 영상을 먼저 검사했습니다. 13항목을 모두 통과해 UPLOAD READY가 나왔습니다.
- 같은 영상의 사본을 화면 중앙만 확대하고, 앞 3초를 검은 화면으로 바꾸고, 소리를 지워
  만든 뒤 같은 검사를 돌렸습니다. NOT READY가 나왔습니다.

이 장의 완료 기준은 다섯 가지입니다.

| | 확인 항목 | 결과 |
|---:|---|---|
| 1 | 검사 기준이 한 곳에 모여 있고 다음 영상에도 그대로 쓰인다 | 통과 |
| 2 | 정상 영상은 통과하고 UPLOAD READY를 받는다 | 통과 |
| 3 | 망가뜨린 영상은 같은 기준에서 실패 판정을 받는다 | 통과 |
| 4 | 숫자로 판단하기 어려운 화면은 대표 장면을 뽑아 AI가 확인한다 | 통과 |
| 5 | 하나라도 실패하면 영상을 자동으로 고치거나 올리지 않고 멈춘다 | 통과 |

## 자동 검사도 해봤습니다

통과 개수만으로는 검사가 실제로 작동하는지 알 수 없습니다. 그래서 같은 13항목을 정상
영상과 손상본에 나란히 돌렸습니다.

| 검사 항목 | 정상 영상 | 손상본 |
|---|---|---|
| 파일이 열린다 | 통과 | 통과 |
| 길이가 정해둔 범위 안이다 | 통과 -- 53.081초 | 통과 -- 52.933초 |
| 영상이 하나 들어 있다 | 통과 | 통과 |
| 소리가 하나 들어 있다 | 통과 | **실패 -- 0개** |
| 1080×1920이다 | 통과 | 통과 |
| 세로 비율이다 | 통과 | 통과 |
| 영상 형식이 h264다 | 통과 | 통과 |
| 소리 형식이 aac다 | 통과 | **실패 -- 소리 없음** |
| 파일 전체가 오류 없이 읽힌다 | 통과 | 통과 |
| 실제로 들리는 소리가 있다 | 통과 -- 평균 -27.2dB | **실패 -- 측정할 소리 없음** |
| 긴 검은 화면이 없다 | 통과 | **실패 -- 0.00~3.00초 검은 화면** |
| 대표 장면을 뽑는다 | 통과 | 통과 |
| 화면을 AI가 확인한다 | 통과 | **실패 -- 자막·잘림·화면 깨짐 3항목** |

정상 영상은 13항목 전부 통과해 `UPLOAD READY`, 손상본은 5항목이 실패해 `NOT READY`가
나왔습니다. 결과 파일은 [artifacts/](artifacts/)에 그대로 공개합니다.

여러분이 직접 돌릴 수 있는 검사도 Source 안에 함께 있습니다.
[chapters/ch17/source/ai-shorts-maker/tests/](../../chapters/ch17/source/ai-shorts-maker/tests/)
폴더에서 찾는 검사는 모두 19건이고, 그중 4건이 이 장에서 새로 생긴 것입니다. 공개
Source에는 대용량 정상·손상 MP4가 없어 영상이 필요한 3건은 건너뛰고 16건이 통과합니다. 이 장의
4건은
[test_chapter17_review.py](../../chapters/ch17/source/ai-shorts-maker/tests/test_chapter17_review.py)에
있고, 나머지 15건은 16장에서 만든 기본 제작 검사와 대본 검수 Gate 검사로 17장 Source에도
그대로 들어 있습니다.

책을 쓰면서 저자가 직접 돌린 것은 다음과 같습니다. 완성 영상과 손상본을 같은 검사기에
다시 넣어 13항목의 값을 하나씩 대조했고, 검사기를 두 번 실행해 화면 판단이 없는 첫
실행에서는 정상 영상도 `NOT READY`가 나오는 것을 확인했습니다. 대표 장면 이미지도 다시
만들어 책에 실린 것과 같은 파일인지 대조했습니다.

`UPLOAD READY`는 공개해도 된다는 허가가 아니라 정해둔 업로드 전 검사를 모두 통과했다는
뜻입니다.

## 직접 확인해볼 수 있습니다

책의 17장을 그대로 따라 하시면 됩니다. 요청문은
[chapters/ch17/prompts.md](../../chapters/ch17/prompts.md)에 책에 나오는 순서대로
있습니다. 손상본을 만드는 문장도 함께 있어서 검사기가 실제로 문제를 찾아내는지 직접
볼 수 있습니다.

정상 영상인데 실패로 나왔을 때는 검사 기준을 느슨하게 바꾸기 전에 어느 항목이
실패했는지부터 봅니다.

```text
정상 영상인데 검사에서 실패했어.
어느 항목이 어떤 값 때문에 실패했는지 항목별로 그대로 보여줘.
원인을 확인하기 전에 검사 기준을 느슨하게 바꾸거나 항목을 빼지는 마.
```

## 이런 한계가 있습니다

- **이 검사는 파일과 화면 상태를 봅니다.** 내용이 사실인지, 저작권이 있는 소재를 썼는지,
  주제가 사람들에게 잘 맞는지는 판단하지 않습니다.
- **대표 장면으로 화면을 확인합니다.** 전체 프레임을 하나씩 보지 않으므로, 아주 짧게
  스치는 문제는 전체 영상을 직접 재생해서 확인하는 것이 좋습니다.
- **길이 범위는 여러분이 정하는 값입니다.** 이 검증에서는 40~90초로 두었습니다. 다른
  길이의 영상을 만들면 기준도 그에 맞게 정하면 됩니다.
