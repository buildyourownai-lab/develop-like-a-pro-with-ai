# 부록 D. 이 책에서 사용한 API Key와 OAuth 다시 찾기

## 이 부록으로 하는 일

실습에서 발급받은 값과 승인한 권한을 다시 찾고, 필요하면 새로 발급받거나 정리합니다.
API Key는 값이고 OAuth는 승인이므로 정리하는 방법도 다릅니다. Key는 폐기하고 새로
받으면 되고, OAuth는 내 계정에서 철회합니다.

서비스별로 어느 화면에서 발급받았는지는 부록 D의 표에 있습니다. 여기에는 그 뒤에
실제로 하는 일만 두었습니다.

화면 변경을 반영한 관리 경로는 [guides/credential-paths.md](guides/credential-paths.md)에
확인일과 함께 유지합니다.

## 프롬프트

[prompts.md](prompts.md)에 이 부록에서 Claude Code에 입력하는 문장이 책의 순서대로
있습니다.

## 순서대로 합니다

**1. 값이 필요한 것 같을 때 먼저 물어봅니다** --- 실습에서 실제 값은 코드와 Git 밖의
파일에 넣어두었으므로 값을 다시 확인할 일은 거의 없습니다. 요청문은
[prompts.md](prompts.md)의 「값이 아니라 자리만 기억하면 됩니다」에 있습니다.

값 자체는 인증값 파일에만 둡니다. 대화창이나 다른 파일에 붙여넣지 않고 화면 캡처에도
담지 않습니다.

**2. 새로 발급받을 때는 순서를 지킵니다** --- 새로 발급받고 바꿔서 확인한 뒤에 이전 값을
폐기합니다. 먼저 폐기하면 그사이 서비스가 멈춥니다. 요청문은 [prompts.md](prompts.md)의
「새 Key로 교체합니다」에 있습니다.

인터넷에 올린 서비스가 쓰는 값은 내 컴퓨터의 인증값 파일과 배포한 곳에 각각 있습니다.
하나만 바꾸면 내 컴퓨터에서는 되는데 올린 화면에서만 안 되는 상태가 됩니다. 배포한 곳의
값은 Vercel 프로젝트의 Settings > Environment Variables입니다.

```text
https://vercel.com/dashboard
```

**3. 승인한 권한을 철회할 때는 내 계정에서 합니다** --- Google 계정에 연결된 앱 목록을
열면 이 책에서 만든 업로드 도구가 있습니다. 18장과 20장에서 두 번에 걸쳐 승인했지만
철회는 한 번에 됩니다.

```text
https://myaccount.google.com/connections
```

실습을 계속할 생각이라면 철회하지 않고 그대로 두어도 됩니다.

**4. 실습을 끝내고 정리합니다** --- 계속 쓸 서비스는 그대로 두고, 더 쓰지 않을 Key는
서비스에서 폐기하고 OAuth 승인은 계정에서 철회합니다. 배포한 서비스를 내릴 때는 배포한
곳의 프로젝트를 먼저 정리하고 그다음에 인증값을 폐기합니다.
