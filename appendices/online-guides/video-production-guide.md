# AI 영상 제작 가이드 — 장면 설계, 프롬프트, 검수

2026-10-12 작성. Kling 3.0 공식 가이드, 유튜브 제작자가 공개한 설명·프롬프트, 제작 사례 기사와 로마 콘크리트 제작 경험을 종합했다. 다른 영상에서도 재사용하는 실무 문서다. 제작 정책·저작권·계정 승인 규칙은 해당 프로젝트의 정본을 따른다.

## 1. 먼저 무엇을 전달할지 정한다

프롬프트는 장면을 만드는 지시다. 보기 좋은 화면의 수식어만 늘리지 말고 **관객이 무엇을 보고 어떤 사실을 이해해야 하는지** 한 문장으로 적는다. 그다음 그 사실이 드러나는 대상·구도·움직임을 선택한다.

예를 들어 균열 치유를 설명하는 장면의 목적은 ‘신비로운 결정이 반짝인다’가 아니라 ‘균열 벽에 붙은 고체가 틈 안쪽을 채워 물길을 막는다’다. 빛나는 액체나 표면의 흰 거품은 화려하더라도 이 목적에 맞지 않는다.

과학 설명에서는 실제 사진·실제 실험 영상·AI 시각화를 구분한다. 생성 화면을 연구 결과의 증거로 사용하지 않는다. 연구의 경과 시간을 몇 초짜리 영상으로 압축했다면 시간 경과를 설명하는 자막을 편집 단계에서 붙인다.

## 2. 조사하고 참고 장면을 분석한다

공식 모델 가이드로 기능과 입력 방식을 확인하고, 제작 사례로 장면을 설계하는 방법을 공부한다. 유튜브 제목이나 검색 요약만 보고 효과가 검증됐다고 판단하지 않는다. 공개 설명, 공개 프롬프트, 자막, 실제 재생 화면 중 **어디까지 확인했는지** 기록한다.

참고 장면에서는 다음을 따로 적는다.

| 관찰 항목 | 질문 |
|---|---|
| 전달 목적 | 이 장면은 무엇을 이해시키거나 느끼게 하는가? |
| 구도 | 대상은 어디에 있고, 화면에서 얼마나 큰가? 자막 공간은 있는가? |
| 색상 | 주된 색과 강조색은 무엇인가? 어느 대상에 쓰였는가? |
| 질감 | 돌·유리·금속·피부가 서로 다르게 보이는 이유는 무엇인가? |
| 조명 | 빛은 어디서 오는가? 부드러운가? 반사광과 그림자는 어디에 있는가? |
| 카메라 | 촬영 각도와 화면 크기는 무엇인가? 카메라는 실제로 이동하는가? |
| 시간 | 어느 순간에 변화가 시작되고 어떤 상태로 끝나는가? |
| 연결 | 앞뒤 장면과 대상·색감·조명·움직임이 어떻게 이어지는가? |

참고 자료의 구도나 제작 원리를 배우되 외부 영상·프롬프트를 그대로 복제하지 않는다. 상업적인 제작자 설명과 공급자의 홍보 기사는 독립적인 성능 검증과 구분한다. 다른 모델이나 다른 플랫폼의 기능을 현재 MCP에서도 쓸 수 있다고 가정하지 않는다.

## 3. 공통 미술 기준을 먼저 만든다

여러 장면을 만들기 전에 아래 표를 프로젝트별로 채운다. ‘cinematic’, ‘premium’, ‘realistic’만으로는 각 장면의 색감과 질감이 통일되지 않는다.

| 항목 | 적을 내용 | 로마 콘크리트의 적용 예 |
|---|---|---|
| 표현 방식 | 실사풍·회화풍·설명용 단면 등 한 가지 기준 | 절제된 회화적 사실감의 역사 장면, 명료한 과학 시각화 |
| 색상 | 주색·보조색·강조색과 각각의 대상 | 풍화된 회백색 돌, 낮은 채도의 청록 그림자, 역사 장면의 옅은 호박색 햇빛 |
| 재료 | 표면의 거칠기·광택·투명도 | 거친 무광 콘크리트, 불규칙한 어두운 골재, 조밀한 밝은 광물, 투명한 유리 |
| 조명 | 광원 방향·크기·색·명암의 정도 | 역사 장면은 부드러운 측면 햇빛, 물 비교 장면은 중립적인 흰 확산광 |
| 초점 | 무엇을 선명하게 하고 무엇을 흐리게 할지 | 비교할 두 시료와 출구는 동시에 선명하게, 배경만 부드럽게 |
| 카메라 | 높이·각도·이동 원칙 | 건축은 느린 이동, 실험 비교는 고정된 정면 |
| 자막 | 나중에 글자를 놓을 영역 | 하단 핵심 출구를 가리지 않는 위치에 편집 자막 배치 |

공통 화풍을 지키기 위해 모든 장면을 같은 색으로 물들이지는 않는다. 투명한 물을 설명하는 화면에 따뜻한 주황빛을 강하게 비추면 물이 노랗게 보일 수 있다. 이 장면에서는 물과 유리는 중립적인 흰빛으로 읽히게 하고 색의 통일감은 배경과 돌에서 만든다.

색상 코드, 조리개 값, 렌즈의 초점거리 등을 사용할 수 있지만 생성 모델의 물리적인 설정값이나 정확한 색 재현 보장은 아니다. ‘85mm 느낌의 왜곡이 적은 정면 구도’처럼 그 값으로 원하는 효과를 함께 설명한다. 결과의 실제 색과 시야는 따로 확인한다.

## 4. 이미지 지시와 영상 지시를 나눈다

**기준 이미지에는 대상·구도·색·질감·조명·초점을 정한다. 영상에는 그 상태에서 무엇이 어떻게 변하는지 정한다.** 이미지가 잘못됐으면 영상 프롬프트로 동시에 구제하려고 하지 않는다.

정지 이미지가 이미 거품, 큰 파괴 틈, 노란 물, 부정확한 건축을 포함하면 모델이 그것을 출발점으로 유지할 수 있다. 먼저 해당 이미지의 문제를 고친다. 균열이 열린 상태에서 결정이 자라야 한다면, 이미 메워진 이미지를 시작 프레임으로 넣지 않는다.

시작·끝 프레임을 사용할 때는 두 프레임의 카메라, 대상 크기, 골재 위치, 조명, 색상이 같아야 한다. 다른 단면으로 끝나면 틈이 메워지는 대신 시료 전체가 변형될 수 있다. 끝 프레임은 최종 상태를 유도하는 입력이지 중간 동작의 정확성을 보장하는 증거가 아니다.

직접 그린 도식이나 편집한 참조를 쓰면 그 제작 방법을 기록한다. 실제 실험이나 실행 화면을 수정해서 성공한 것처럼 만들지 않는다. 조악하게 붙인 참조도 최종 자산으로 사용하지 않는다.

## 5. 한 장면의 프롬프트를 쓰는 순서

다음 순서는 이 프로젝트가 채택한 작성 틀이다. 모든 모델의 공식 필수 문법은 아니다.

1. **목적과 대상:** 보여줄 대상, 개수, 규모, 관객이 봐야 할 변화.
2. **환경과 구도:** 배경, 대상 위치, 화면을 차지하는 비율, 촬영 각도, 자막 공간.
3. **색상·재료·조명:** 어떤 물체에 어떤 색과 질감을 쓰는지, 광원의 방향과 성질.
4. **카메라와 초점:** 고정 또는 이동 하나를 선택하고 속도·방향·초점 대상을 적는다.
5. **시간에 따른 동작:** 시작 상태, 핵심 변화, 종료 상태, 마지막 유지 구간.
6. **유지할 형상:** 변하면 안 되는 대상의 위치·크기·개수·재료 배치.
7. **음향:** 필요한 환경음, 별도로 넣을 내레이션·음악과의 구분.
8. **핵심 제외 조건:** 실제로 문제가 된 오류를 짧고 구체적으로 적는다.

긍정적인 지시를 먼저 쓴다. ‘누수 금지’만 적지 말고 ‘왼쪽 균열의 아래 출구와 받침은 끝까지 마른 상태’라고 지정한다. 금지사항을 길게 반복한다고 품질이 좋아지는 것은 아니다.

### 카메라 용어는 원하는 효과와 함께 쓴다

| 지시 | 뜻 | 사용할 때 주의할 점 |
|---|---|---|
| 고정 촬영 | 카메라 위치·각도·화면 크기 유지 | 실험 비교와 작은 재료 변화를 읽기 좋다 |
| 돌리 인 | 카메라가 대상 쪽으로 이동 | 단순 확대와 구분하고 이동 경로를 하나로 정한다 |
| 줌 인 | 카메라 위치를 유지하며 화면 확대 | 돌리 이동과 동시에 요구하지 않는 편이 통제하기 쉽다 |
| 팬·틸트 | 제자리에서 좌우·위아래로 방향 변경 | 회전 방향과 종료 구도를 적는다 |
| 트래킹 | 움직이는 대상을 따라 카메라 이동 | 대상 속도와 카메라 속도의 관계를 정한다 |
| 오빗 | 대상 주변을 돌아 촬영 | 새로 드러나는 뒷면의 일관성을 검수해야 한다 |

‘카메라를 고정하고 앞으로 이동해’처럼 모순된 문장을 제거한다. 한 번의 생성에 이동·회전·초점 이동·여러 재료 변화까지 모두 넣으면 어떤 지시가 실패했는지 찾기 어려워진다. 설명 장면에서는 전달에 필요한 동작을 우선한다.

## 6. 프롬프트를 제출하기 전에 리뷰한다

아래 질문에 실제로 답하고, 수정한 문장과 이유를 남긴다. 작성자가 확인했다면 **자체 리뷰**, 별도의 사람이 검토했다면 실제 검토 범위와 함께 그 사실을 기록한다. 리뷰 문서를 만들었다는 이유로 생성 결과를 통과 처리하지 않는다.

| 항목 | 확인할 내용 |
|---|---|
| 의미 | 화면의 변화가 내레이션과 같은 사실을 설명하는가? |
| 형상 | 시작 이미지에 필요한 대상과 올바른 상태가 실제로 있는가? |
| 구도 | 작은 변화와 비교 출구를 동시에 읽을 수 있는가? |
| 미술 | 색상·재료·조명·초점이 구체적이며 서로 충돌하지 않는가? |
| 시간 | 설정한 길이 안에 동작이 가능하며 마지막 상태를 볼 시간이 있는가? |
| 카메라 | 서로 모순된 이동 지시나 불필요한 컷 전환이 없는가? |
| 물리 | 고체를 액체처럼, 물을 점성 물질처럼 표현하게 하는 단어가 없는가? |
| 연결 | 이전·다음 장면과 같은 대상과 재료 배치를 유지하는가? |
| 기능 | 선택한 모델과 실제 도구가 해당 입력·길이·음향을 지원하는가? |
| 비용 | 현재 잔량, 이번 작업 비용, 남은 필수 장면과 재시도 범위를 확인했는가? |
| 검수 | 어떤 결과를 수용하고 어떤 결과를 제외할지 정했는가? |

외부의 좋은 예제도 그대로 믿지 않는다. 이번에 읽은 유튜브 공개 프롬프트 문서에는 한 장면에서 카메라가 따라가고 올라갔다가 내려오는 지시 뒤에 ‘카메라는 계속 고정’이라는 문장이 함께 있었다. 공개 자료에도 편집 오류가 있을 수 있으므로 원리만 가져오고 현재 장면에 맞게 모순을 제거한다.

## 7. 결과를 보고 고친다

영상은 시작·중간·끝뿐 아니라 전편을 확인한다. 빠르게 지나가는 형상 변형, 마지막 순간에 생긴 거품, 잠깐 새는 물은 정지 이미지 하나로 발견하기 어렵다. 접촉시트는 변화를 비교하는 보조 자료이고 재생 검수를 대신하지 않는다. 소리도 별도로 확인한다.

문제를 ‘별로다’라고 남기지 말고 **파일·시점·관찰한 형상·전달에 미치는 영향**으로 적는다. 예를 들어 ‘6초에서 흰 고체가 표면 밖으로 길게 늘어나 결정 성장보다 페이스트 유출처럼 보임’이라고 기록한다.

한 번에 핵심 원인 하나를 바꾼다. 구도·광원·모델·동작을 모두 바꾸면 무엇이 개선됐는지 알기 어렵다. 같은 오류가 반복되면 문장을 더 늘리기 전에 기준 이미지와 제작 방식을 다시 본다. 단순 확대·편집·정확한 도식으로 충분한 장면인지도 판단하되 기존 제작 계약과 맞추고 방법을 기록한다.

예산이나 생성 횟수의 상한을 따로 정하고 자동 결제하지 않는다. 크레딧이 남아 있다는 이유로 실패를 계속 반복하지 않는다. 공개할 수 있는 결과가 없으면 미완료로 기록한다.

## 8. 이번 제작에서 얻은 경험

다음은 문서에서 읽은 일반론이 아니라 로컬 자산에서 관찰한 결과다. 모델 전체의 성능으로 일반화하지 않는다.

| 실제 관찰 | 배운 점 | 다음 지시에서 바꿀 것 |
|---|---|---|
| 비교 시료에 넓은 흰 가루띠와 열린 큰 틈이 반복됨 | 시작 이미지의 잘못된 형상이 참조 편집에도 남을 수 있다 | 영상 전에 좁은 초기 균열과 내부의 조밀한 고체 이음을 확정 |
| 비교 시료의 크기·공급수 높이가 서로 달랐음 | ‘동일한 조건’이라는 추상 문장만으로는 비교 구도가 고정되지 않았다 | 시료 위치·외형·초기 균열·공급 장치·수위·출구를 각각 비교 |
| 물이 노랗거나 굵고 점성 있는 흐름으로 보였음 | 색상과 조명이 물리적 의미까지 바꿀 수 있다 | 물·유리에 중립광, 작은 분리된 물방울, 위치와 낙하 방향 명시 |
