# 부록 B. 막혔을 때 다시 시작하는 법 — 상세 안내

실습이 책과 똑같이 흘러가지 않아도 처음부터 다시 만들 필요는 없습니다.

**디버깅 → 내 정상 기록으로 복구 → 장별 Source로 재시작**

앞 단계에서 해결되면 거기서 멈춥니다. 표에서 지금 상태에 맞는 출발점을 고릅니다.

| 지금 상태 | 어디로 |
|---|---|
| 오류 메시지가 보이고 원인을 아직 모릅니다 | 1단계 |
| 원인을 확인해 수정했지만 같은 문제가 계속됩니다 | 2단계 |
| 프로젝트가 어디서부터 어긋났는지 모르겠습니다 | 2단계 |
| 정상 기록으로 돌아가도 그 장을 끝내지 못했습니다 | 3단계 |
| 디버깅으로 해결하지 못했고, 아직 돌아갈 정상 기록도 없습니다 | 3단계 |

## 돌아갈 기록이 실제로 남았는지 확인합니다

| 방법 | 기록을 남기는 때 | 사람이 확인할 것 |
|---|---|---|
| Checkpointing | Claude Code가 요청을 실행할 때 최근 변경을 되돌릴 수 있는 복구 지점을 자동으로 관리합니다 | 어느 요청 전으로 돌아가며 어떤 파일이 대상인지 |
| 공통 작업 원칙에 따른 Git 기록 | 주요 작업이 검사에 통과하면 Claude가 기록합니다 | 검사를 실행했고 필요한 파일이 실제로 기록됐는지 |
| 「마무리하자」 | 5장의 공통 원칙에 따라 정상 상태를 기록하고 GitHub에 보냅니다 | 어떤 기록을 보냈고 전송이 끝났는지 |

공통 지침은 행동을 강제하는 장치가 아닙니다. **기록했다는 설명과 실제 기록을 함께
확인합니다.** 별도로 GitHub 전송을 금지한 작업에서는 그 지시를 따릅니다.

준비편의 설치·로그인 문제는 Source를 바꿔도 해결되지 않습니다. 아직 프로젝트를 열지
못했다면 준비편의 「이 장에서 막혔다면」부터 확인합니다.

## 1단계. 디버깅

작업하던 대화창에 하려던 일, 기대한 결과, 실제 결과와 오류 메시지를 알려줍니다.
**메시지에 인증값이나 개인정보가 있으면 그 부분을 가립니다.** 먼저 같은 문제가 다시
나타나는지 확인하고, 원인을 좁힌 뒤 수정합니다.

~~~prompt
방금 무엇을 하려고 했고, 무엇을 기대했고, 실제로 무엇이 일어났는지 알려줄게.
바로 고치지 말고 같은 문제가 다시 일어나는지 먼저 확인해줘.
원인을 찾으면 그 부분만 고치고, 같은 문제가 해결됐는지 다시 확인해줘.
~~~

오류 메시지를 직접 해석할 필요는 없습니다. 비밀값을 가린 메시지와 작업 상황을 함께
전달하면 됩니다. 이전 대화가 없다면 같은 프로젝트 폴더에서 새 대화를 엽니다.

같은 문제를 몇 번 고쳐도 진전이 없다면 2단계로 갑니다. 시도 횟수보다 무엇이
확인됐고 무엇이 아직 다른지를 먼저 봅니다.

## 2단계. 내 정상 기록으로 복구

책이 제공하는 파일이 아니라 **내 프로젝트에 실제로 남긴 정상 기록**으로 돌아갑니다.
먼저 현재 작업을 따로 보존하고, 아직 Git에 기록하지 않은 파일까지 포함됐는지 확인합니다.

~~~prompt
현재 작업을 먼저 안전하게 보존하고, 이 프로젝트에서 마지막으로 정상
동작했던 상태를 찾아줘.

현재 상태와 무엇이 다른지 확인한 뒤 마지막 정상 상태로 안전하게
복구해줘.

복구가 끝나면 관련 테스트를 다시 실행해 정상적으로 돌아왔는지 확인해줘.
~~~

복구 뒤 관련 Test와 필요한 결과물을 확인한 다음 막혔던 작업을 다시 요청합니다.
**Test 통과는 검사한 조건을 만족한다는 뜻이지, 하려던 새 작업까지 완성됐다는 뜻은
아닙니다.** 돌아갈 기록이 없다면 3단계로 갑니다.

## 3단계. 장별 Source로 재시작

앞의 두 방법으로도 그 장을 끝내지 못했을 때 쓰는 마지막 안전망입니다.

~~~prompt
Development Lab
https://www.studyailab.com/develop
에서 지금 진행 중인 장의 소스·검증 안내를 열고, 연결된 장별 Source를 찾아줘.

내 현재 작업을 먼저 안전하게 보존해줘.

그 장을 끝낸 Source에서 다시 시작하고 관련 테스트를 실행해줘.
~~~

진행 중인 장 번호를 함께 알려주고, Claude가 고른 Source가 **그 장을 마친 상태**인지
확인합니다. 어느 장인지 확정할 수 없다면 먼저 정한 뒤 진행합니다. 이번에는 내 기록이
아니라 저자가 제공한 완성 파일에서 출발합니다.

![그림 B-1 | 되돌릴 때 파일을 어디서 가져오나 --- 2단계는 내 컴퓨터의 기록에서, 3단계는 공개 저장소에서 파일을 가져오며, 인증키를 다시 넣어야 하는지도 서로 다릅니다.](https://www.studyailab.com/develop/guides/appendix-b/figure-b-01-where-it-comes-from.svg)

인증값은 Source에 들어 있지 않습니다. 부록 D의 방법으로 필요한 값의 이름과 위치를
확인하고 직접 입력합니다. **실행 환경·인증·관련 Test가 준비된 뒤** 다음 장으로 이어갑니다.
Source를 받는 것만으로 로그인이나 외부 서비스 승인이 끝나는 것은 아닙니다.

## 보존한 작업에서 필요한 것만 다시 가져옵니다

복구 전에 보존한 작업의 위치와 파일·변경 목록을 확인합니다.
인증값 파일은 위치와 존재 여부만 확인하고 실제
값은 대화에 출력하지 않도록 주의합니다.

~~~prompt
되돌리기 전에 보존해둔 작업이 지금 어디에 있는지 알려줘.
Git에 기록되지 않았던 파일까지 포함해서 파일과 변경 목록을 보여줘.
인증값 파일은 위치와 존재 여부만 알려주고 실제 값은 출력하지 마.
그중에 지금 상태로 다시 가져올 만한 것이 있으면 알려줘.
~~~

**「Git에 기록되지 않았던 파일까지 포함해서」 줄을 함께 사용합니다.** 메모나 설정
파일도 목록에서 확인하기 위한 조건입니다. 살릴 파일을 고른 뒤 필요한 것만 가져오고,
관련 Test를 다시 확인합니다. 전체를 한꺼번에 덮으면 복구한 상태가 다시 깨질 수 있습니다.

기록을 화면으로 보려면 부록 C를 참고합니다. Sourcetree를 설치하지 않아도 위
네 요청문으로 복구를 진행할 수 있습니다.

> **한 번도 막히지 않는 것이 아니라, 막혀도 다시 이어가는 것이 목표입니다.**


## 내 상태를 확인한 뒤 필요한 복구만 합니다

먼저 “현재 진도 알려줘”라고 요청해 마지막 확인과 현재 프로젝트의 차이를 봅니다. 힌트나 비교 요청만으로 복구를 실행하지 않습니다. 복구가 필요하면 현재 작업의 안전 사본과 실제 위치를 확인하고, Git에 기록되지 않은 메모·설정까지 무엇이 보존되는지 확인합니다. Secret은 공개 자료나 원격 지원 기록에 보내지 않습니다.

현재 장을 다시 연습하려면 START, 그 장을 마친 상태에서 다음으로 가려면 FINISH를 선택합니다. 어떤 상태를 고를지 모호하면 먼저 정합니다. 복원 뒤 관련 검사를 다시 실행하고 개인 인증값은 안전한 입력 위치에서 직접 준비합니다. 예제를 실행한 것과 내가 처음부터 구현한 것을 같은 경험으로 기록하지 않습니다.


### 자동화와 공개 기능은 먼저 멈춥니다

20장의 답글 전송 결과가 불분명할 때는 코드를 되돌리기 전에 자동 전송을 멈추고 실제 댓글과 기록을 대조합니다. Git 복구는 이미 YouTube에 보낸 답글을 취소하지 않습니다. 21~22장의 대화는 먼저 해당 기능만 끌 수 있으며, 원래 주식 화면까지 다시 만들 필요는 없습니다.
