## 무엇을 확인할지 고릅니다

| 하고 싶은 것 | 여는 곳 |
|---|---|
| 그 장의 요청문을 복사하기 | 해당 장 → 커맨드 |
| 막힌 장을 끝낸 상태에서 다시 출발하기 | 해당 장 → 소스·검증 → 장별 완성 소스 |
| 저자가 만든 결과물과 내 것을 비교하기 | 소스·검증 → 저자 검증 상세 기록의 결과물 링크 |
| 저자가 무엇을 어떻게 확인했는지 읽기 | 해당 장 → 소스·검증 |

![화면 A-3 | 1장 검증 결과물 폴더 --- `verification/chapter-01/artifacts` 경로에서 Excel 결과물·검사 코드·검사 결과·KOBIS 대조 자료를 확인합니다.](https://www.studyailab.com/develop/guides/appendix-a/screen-a-03-artifacts.png)

Excel처럼 브라우저에서 내용을 바로 볼 수 없는 파일은 내려받아 엽니다. 비교를 맡기려면
해당 장의 검증 안내에서 결과물 링크를 찾고, 아래 요청과 함께 그 주소를 전달합니다.

~~~prompt
이 주소에 있는 1장 결과물을 내 컴퓨터에 받아줘.
내가 만든 Excel과 시트 이름과 항목이 같은지 나란히 비교해서 알려줘.
~~~

배치나 색이 저자의 결과물과 똑같을 필요는 없습니다. **내 결과물이 그 장의 완료 조건과
확인 목록을 만족하는지** 봅니다.

장별 Source는 **그 장을 마친 상태로 다시 시작하는 마지막 안전망**입니다. 먼저 디버깅하고,
내 정상 기록으로 돌아가도 진행하기 어려울 때 사용합니다. 복구 순서와 네 요청문은 부록 B에
있습니다.

Source에는 여러분의 인증값이 없습니다. 필요한 환경과 인증값을 준비하고 관련 Test까지
확인한 뒤 이어갑니다. 인증값을 넣을 위치를 확인하는 방법은 부록 D에서 찾습니다.

## Test와 공개 검증은 역할이 다릅니다

| 자료 | 어떻게 사용하나 | 확인할 수 있는 범위 |
|---|---|---|
| Test | 내 프로젝트에서 실행합니다 | 검사에 포함된 완료 조건을 지금 지키는지 |
| 공개 검증 | 저자의 실행 기록을 읽고 비교합니다 | 저자가 당시 어떤 환경에서 무엇을 실행하고 확인했는지 |

Commit에는 무엇을 언제 바꿨는지가 남습니다. 기록을 화면으로 보려면 부록 C를, 결과와
판단 근거를 다른 사람에게 보여주려면 부록 G를 봅니다.

내 프로젝트에도 같은 기본 흔적을 남길 수 있습니다.

~~~prompt
이 프로젝트도 다른 사람이 열어봤을 때 무엇을 만든 것인지 알 수 있게 정리해줘.
README에 무엇을 만들었고 결과물이 어디에 있고 어떻게 확인하는지 적어줘.
확인에 사용한 검사도 함께 두고, 지금 상태가 정상인지 확인한 뒤 Git에 기록해줘.
~~~

> **결과물과 확인한 기록을 함께 남기면, 무엇을 만들고 어디까지 확인했는지 다시 살펴볼 수 있습니다.**


## 장별 명세와 실습 자료는 역할이 다릅니다

`chapter.json`은 장의 목표·시작 조건·완료 기준을 정한 안내입니다. `tutor.md`는 튜터가 그 장을 지도할 때 참고하는 설명이며, `prompts.md`는 독자가 본문과 같은 순서로 복사하는 요청문입니다. 파일 존재·파일을 읽은 것·실제로 실행한 결과는 서로 다릅니다.

START는 해당 장에 진입할 때의 기준 상태, FINISH는 해당 장을 마친 기준 상태입니다. 순서대로 진행하는 독자는 자기 프로젝트를 이어갑니다. 자료를 비교하는 것은 프로젝트 전체를 교체하는 것이 아닙니다. 원본 소스가 연결되지 않은 항목은 미연결로 표시하고 다른 코드로 대신해 확인했다고 하지 않습니다.
